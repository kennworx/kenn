JSONL sidecar streams: a producer must never let a PARTIAL record reach the parser, and a consumer must never assume read_line returned a whole record. Two independent bugs, both invisible to small fixtures and both fatal on real workspaces (measured: a 1553-file TypeScript repo indexed 0 files). (1) CONSUMER, crates/kenn-indexer/src/transform_jsonl/ingest.rs::next_jsonl_line: BufReader::read_line stops at '\n' OR EOF, so a mid-record flush comes back as a non-newline-terminated fragment; the old code returned it as a complete line and the parser died with 'EOF while parsing a string'. Only accept a line that ends_with('\n'); on a fragment keep it in the buffer (do NOT clear) and poll again — read_line appends, so the remainder lands after it. Producers flush on buffer boundaries, and a pipe flushes at 64KiB, which lands mid-record on any large stream. (2) PRODUCER, indexers/kenn-ts/src/main.ts: NEVER process.exit() with queued stdout. stdout to a pipe is async in Node/Bun; process.exit discards whatever is still queued, which silently dropped ~89% of frames (7,492 of 69,125 lines). Use process.exitCode and let the runtime drain. (3) The wire is stdout, so ANY child process that inherits fd 1 corrupts it — a trimmed dotnet SDK image made MSBuildLocator shell out to 'dotnet --list-sdks' and its output became line 1 of the stream. A sidecar that spawns children should dup the protocol stream to a private fd and repoint fd 1 elsewhere. TEST RULE: a growing-file ingest test that writes the whole file before reading cannot fail — split a record across two flushes with the producer still alive.
