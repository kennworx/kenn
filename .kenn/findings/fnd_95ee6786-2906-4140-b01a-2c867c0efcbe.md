Sharing a rule between two surfaces is NOT enough — share the FACTS it needs, by persisting them. A shared predicate still diverges when one caller cannot supply an input: it will fabricate one, and a fabricated argument to a shared function looks like agreement while producing disagreement.

Concretely: `domains::is_domain_eligible` was already shared by the atlas producer and the domains query, but its `example` fact came from a producer-side path join (primary_def_file -> files -> is_example_path). AggregateNodeRow carries no path, so the query passed `example: false` and reported an 11th domain on this repo whose entire cross-package span was four functions in crates/kenn-store/examples/ — a throwaway spike posing as architecture. The atlas rendered 10; nothing said which surface lied.

The fix is to move the FACT into the data, not to teach each consumer the join. `example` now sits on AggregateNodeRecord/AggregateNodeRow beside `test` and `external` — the three provenance flags — evaluated ONCE in aggregate.rs build_aggregate_nodes, which already holds `files` and `primary_def_file` for resolve_anchors, so it costs no extra scan.

Persist the FACT, never the VERDICT. Eligibility is policy that differs per axis (the central list, the package axis and the domain axis all want different subsets), so a stored verdict goes stale the moment any of them moves; path provenance is a property of the source tree and cannot. The test to apply when adding a predicate input: can EVERY caller answer this from what it holds? If not, that input belongs on the row.
