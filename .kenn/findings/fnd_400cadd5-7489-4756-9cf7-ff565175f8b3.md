The store `live` entry is a POINTER FILE (a text file naming the active run relative to derived_root), NOT a symlink — that is what lets the atomic flip work unprivileged on Windows (windows-support D1). NEVER treat `live` as traversable: no local/live/<subpath> path joins and no symlink-through-live. Such a path dangles once `live` is a plain file — it bit `atlas_pointer` in cmd_index/core.rs, which had symlinked .kenn/atlas -> local/live/atlas (the proposal wrongly claimed nothing traverses live; a string literal hid it from the live_path().join grep). Resolve `live` via `Layout::live_target()` — the SINGLE reader (`Store::live_target` delegates to it), which reads the pointer with read_to_string so an old-store symlink `live` degrades to None (reindex, no-migration D3) — then join onto the RESOLVED run dir. The sole writer is `atomic_flip_live` (write-temp-fsync-then-rename; breaking that atomicity turns the concurrent-reader test red). One writer, one reader — do not add a second of either.
