kenn's graph and MCP surface are LINE-based, not byte-based. `get_source` returns start_line/end_line, `find_at_location` takes a line, and usage/edge attribution resolves the enclosing symbol by line (`offset_to_line`). Byte offsets are an INTERNAL detail used only to compute the line — never a consumer-facing requirement; an agent cannot seek to a byte, it reads lines.

So when designing an indexing feature or choosing a parser/dependency, target LINE granularity. Do NOT over-engineer for, or select a tool on, byte-precise span fidelity — it buys nothing the surface exposes. (Lesson from the HTML parser spike: byte-offset precision was wrongly treated as a selection axis until corrected; the real bar is "can it give me the line.")
