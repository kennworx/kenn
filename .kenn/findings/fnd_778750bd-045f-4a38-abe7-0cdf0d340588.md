kenn-dotnet targets net10, aligned with the SDK-10 generation (Roslyn Workspaces 5.6, Microsoft.Build 18.x). The old net8 pin was NOT a real version requirement: it followed a net10 attempt that hit an AVE later root-caused to the CopyToAsync pipe-drain (see fnd_b5f1b55b) — already fixed with blocking reads — NOT the .NET version. On a sdk:10 base a net8 sidecar breaks concretely: the framework-dependent binary won't launch (exit 150 — only the net10 runtime is present) and MSBuildLocator returns no instances (a net8 process can't load SDK 10's net10 MSBuild). Keep every MSBuild-touching layer (TFM, Roslyn, Microsoft.Build) on the SAME major as the SDK base. Docker image stays framework-dependent on sdk:10 with no Dockerfile logic change.
