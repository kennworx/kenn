A link target that resolves to no graph node is NOT broken if the workspace holds it. Both corpora run the same rung before dangling: existence (via the injected `relpath::PathExists`, backed by `FsPaths` = `workspace_root.join(p).exists()`, so DIRECTORIES count) -> an `attachment` stub keyed by the CANONICAL path, so every spelling of one on-disk target collapses to one node. Only a target the workspace lacks dangles. Three rules that are easy to get wrong: (1) ELIGIBILITY IS EXISTENCE, NOT SPELLING — HTML's old `is_asset_ref` gate required a non-indexed extension, so an existing `LICENSE-MIT`, a directory, and an excluded `.md` all dangled; the gate is deleted, not widened. (2) ONE KIND RULE, `markdown::existing_target_kind` — Document for a `.md`/`.html` the config excluded, Attachment otherwise — so an on-disk target is never a leaf on one side and a document on the other. (3) ORDER: graph resolution wins, so an indexed source file resolves to its FILE node and is never shadowed by an attachment. The one exception is a BARE NAME on an INLINE link: a CommonMark destination denotes a path, so an existing path beats a same-named code symbol; a wikilink denotes a name and keeps symbol-first (same inline-vs-wikilink split fnd_57faf100 draws for locality). An anchor on an attachment grades drifted, not exact — the target is outside the corpus so its sections were never parsed.
