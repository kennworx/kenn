GOTCHA (fixed): store_finding pre-embeds the finding text ONLY for an advisory near-duplicate probe. A cold embedder (EmbedError::Starting → McpErrorCode::EmbedderStarting) must be treated as "skip the probe" (text_vec = None), never propagated with `?` — otherwise the FIRST store_finding against a freshly-indexed repo (embeddings not built yet) fails with "embedder warming up" and the finding is lost. This mirrors find_directives' non-blocking semantic-leg degrade (`Err(e) if e.code == EmbedderStarting => None`). Found dogfooding the reconcile skill on a large external repo: the first directive seeded against a fresh index errored until the embedder warmed.
