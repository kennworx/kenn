kenn-swift's authoritative scope/noise filtering lives in `Indexer.swift` (the sidecar reader), NOT in Rust config. `SwiftConfig.excludes` are NOT passed to the sidecar — the Rust driver only forwards `--workspace`/`--projects`/`--skip-build`/`--platform`. So to change what the Swift indexer includes/excludes, edit the sidecar, not `kenn.toml`.

Two filters in `Indexer.isUnderWorkspace` / the occurrence loop:
1. DEPENDENCY-TREE EXCLUSION (by path): a source file counts only if under the workspace root AND not under `/.build/` (SwiftPM checkouts), `/.kenn/` (our Xcode derived-data + its SourcePackages), `/DerivedData/`, or `/Pods/` (CocoaPods vendored source). This keeps dependency handling consistent across package managers — kenn indexes the project, not its deps. Pods are excluded BY DEFAULT for parity with SPM, even though `Pods/` is in-tree (unlike SPM's derived checkouts). Without these, deps leak: e.g. swift-nio jumped 658→494 files and Ice 154→116 once added.
2. NOISE-NAME FILTER (`isNoiseName`): skip symbols/edge-endpoints whose name starts with `getter:`/`setter:` (accessors not caught by subkind, incl. external accessor references) or `$s` (macro-expansion symbols, e.g. SwiftUI `#Preview`). `ensureSymId`/`ensureStubId` also drop nodes whose composed KEY starts with `$s` (catches macro MEMBERS whose own name is normal but parent is a `$s` macro struct).
