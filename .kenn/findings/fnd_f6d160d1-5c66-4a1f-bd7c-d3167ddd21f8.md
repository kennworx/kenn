Go indexing assumes the module is ALREADY BUILT before `kenn index` runs — this is a deliberate contract, not a TODO. scip-go shells to `go list` / `go/packages`, so on a COLD module it compiles every missing dependency on the fly and appears to hang: measured on helm (`helm.sh/helm/v4`, full k8s dep tree) cold scip-go ran 12+ min (killed), but after a one-time `go build ./...` (6:53) the SAME scip-go run took 4.8s and produced 53k symbols. So the requirement is a WARM BUILD CACHE, not merely downloaded deps. kenn does NOT run `go build`/`go mod download` on the user's behalf — same hands-off posture as rust-analyzer/Swift; `ScipGo.run_unit` just surfaces scip-go's non-zero exit as `ScipOutcome::Unavailable`. The starter `kenn.toml` `[language.go]` block documents this. Don't "fix" the apparent hang by adding a build step inside the driver.
