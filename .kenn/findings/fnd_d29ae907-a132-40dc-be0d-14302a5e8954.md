md→code links resolve to BOTH code symbols and code files (backlink-first, per the index-markdown design decision). Symbol-target `links_to`/`embeds` edges are fully sound. FILE-target edges are only half-sound: code file rows and symbol rows share the ShortId space within a language partition with no discriminator, and inbound/outbound graph nav hydrates neighbours from the `symbols` table (traversal.rs `fetch_symbols_by_ids`) — so a code-file→md BACKLINK works (list_inbound on the file id finds the md section, which lives in the symbols table), but FORWARD nav from an md node over the edge mis-resolves the file id to the colliding symbol id. Only `contains` / `list_module_files` hydrate file targets safely. Rule: keep file-target md→code edges (they power code→md backlinks, the priority), but EXCLUDE them from any forward md→file listing (e.g. the future check_links tool) until the graph gains a file-target edge discriminator.
