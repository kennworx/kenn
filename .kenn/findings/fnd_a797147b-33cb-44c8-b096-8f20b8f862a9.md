Every production orchestration path that runs the indexing pipeline (`kenn_indexer::index_workspace` or `run_pipeline_with_progress`) MUST build its post-aggregate hook via `kenn_analyze::analysis_hook_from_config(&config, workspace_root)` — never hardcode `kenn_indexer::pipeline::no_op_hook()`. The analysis pass (Louvain clustering → `write_analysis_tables` AND `graph_stat_rows` → `write_stats`) runs ONLY inside that hook. Passing no_op silently drops the analysis tables and the per-language/whole-graph `subset='graph'` stats; entity stats survive (they're built at `finalize`, which every path runs) so the loss is easy to miss — the bug looked like "graph block missing from get_workspace_overview after a watcher/recovery reindex." The two MCP reindex sites (`indexing/orchestrate.rs::run_reindex_and_install` and `indexing/events.rs::spawn_background_reindex`) and CLI `cmd_index.rs` all route through the one helper, which honors `index.persist_analysis` (no-op when disabled). Only test callers may pass `no_op_hook()` directly. `AnalysisHook` and `PostAggregateHook` are structurally identical Box types, so the helper's result drops in wherever a `PostAggregateHook` is expected — this is why kenn-analyze need not depend on kenn-indexer.
