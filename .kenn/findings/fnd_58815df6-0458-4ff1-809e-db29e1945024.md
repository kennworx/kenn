Run the test suite through `just test`, not bare `cargo test` — it pins `KENN_EMBED_IN_PROCESS=1` so embedder backend selection cannot pick up a running `kenn server` daemon. On macOS that daemon returns EMPTY embeddings (the fork+Metal bug), so `kenn-store/tests/hybrid_search.rs` fails 5 of 6 in ~0.2s having embedded nothing.

The tests already set the var themselves, and it is still not enough: they set it from INSIDE each test, the env is process-global, and backend selection races ahead of it, so under parallel execution some tests select the daemon anyway. Serializing (`RUST_TEST_THREADS=1`) hides it; pinning the env for the whole process fixes it. Reproduced on one unchanged tree: daemon up + bare `cargo test` = 5/6 fail in 0.20s; daemon up + `just test` = 6/6 pass in 10.98s; daemon down + bare = 6/6 pass.

Why this keeps biting: `kenn index` and `kenn find` BOTH auto-spawn that daemon, so any session that touched the CLI has one running. "No daemon" is not a safe default, and the failure looks like a code regression rather than an environment one. `KENN_EMBED_IN_PROCESS` is honored only under `cfg!(debug_assertions)` (kenn-embed/src/selector.rs), so it cannot alter a release binary — it is safe to set for every test and coverage run, and `just crap-ci` sets it too.
