Shell-safety flooring is PER-INGESTER, never a general choke point. Each language ingester that builds a pub_id from a file path or free text (markdown, html, css, text) MUST floor it via crate::pubid::floor at its own id-construction sites — the document node, id nodes, selectors, module nodes, AND the resolution lookups that must match the stored floored id. shell-safe-symbol-ids task 2.2 deferred css/html flooring; a real repo (Jazzy HTML docs with bracketed filenames like [ServerTrustEvaluating].html) then panicked the store writer shell-safe debug_assert. Do NOT centralize the floor at a general point such as PublicId::new in kenn-model: it would lossy-collapse RAW code descriptors (rust/ts SCIP) that need per-language STRUCTURAL rendering (backtick-drop, angle-brackets to ~) done in kenn_indexer::pubid, turning a proper generic id into _underscores_. Floor is idempotent, so safe-path ids and already-rendered code ids are unaffected.
