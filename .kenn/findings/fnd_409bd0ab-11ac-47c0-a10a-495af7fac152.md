kenn-swift reads the Swift compiler index store (libIndexStore via swift-index-store). Hard-won internals of `Indexer.swift`, verified empirically against real packages (swift-argument-parser, swift-nio):

RELATION ROLE → EDGE DIRECTION (an occurrence carries `roles` + per-relation roles to a related symbol):
- `calledBy`: occ.symbol is called by `related` → emit `calls` from related → occ.symbol (related is the caller).
- `overrideOf`: occ.symbol overrides `related` → `overrides` from occ.symbol → related.
- `baseOf`: occ.symbol IS a base/protocol of `related` → `implements` from `related` → occ.symbol (NOT the other way — this direction was initially backwards; the occurrence is the base, the related is the conformer).
- `childOf`: `related` is the parent (defined_in).

EXTENSIONS: a Swift extension is not a node and its members are `childOf` the EXTENSION (USR `s:e:…`), and the extension occurrence carries NO relations — so you cannot read the extended type off it. Recover it by stripping `s:e:` and longest-prefix-matching the remainder against defined nominal-type USRs (`resolveParent`). This collapses extension members onto the canonical type (design D3).

STACK-OVERFLOW GOTCHA: `keyFor` recurses up the resolved parent chain. The prefix-resolution can create a parent CYCLE (real, hit on swift-argument-parser → EXC_BAD_ACCESS in `swift_beginAccess`). `keyFor` MUST keep a visiting-set guard (and a `resolved != usr` check) and fall back to the bare name on a cycle. Accessors (subkind get/set/…) are skipped entirely (not nodes); the wire `key` is a readable composed `Module.Type.member(labels:)` (overloads salted with a short USR digest), with the full signature in the separate `sig` field.
