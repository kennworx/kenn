kenn's re-embed/re-index invalidation is gated on hand-maintained constants, NOT derived from indexer code. STORE_SCHEMA_VERSION (meta.rs) gates the graph/FTS rebuild; CODE_TEXT_RECIPE / FINDING_TEXT_RECIPE (embed/sidecar/manifest.rs) gate vector reuse. Consequences when iterating on extraction/embedding logic: (1) 'kenn index' without --force SKIPS on an unchanged git checkout, so after changing extraction logic run 'kenn index --force' (or bump STORE_SCHEMA_VERSION) or you're testing the OLD graph; (2) changing what text is embedded or how it's prompted at embed time (not stored in embeddable_text) leaves the xxh3 fingerprint unchanged, so you must bump CODE_TEXT_RECIPE or wipe .kenn/vectors, else stale vectors are reused even under --force.
