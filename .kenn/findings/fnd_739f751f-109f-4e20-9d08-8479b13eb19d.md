CSS-Modules member binding resolution (Phase 2 §7.3, now IMPLEMENTED — was deferred): pure helpers in `css/usage.rs` (`extract_module_bindings`, `extract_member_accesses`, `class_name_candidates`) + `css/ingest.rs::emit_module_member_usages` (+`resolve_member_class`, `is_js_ts`) in the post-code barrier. For a JS/TS usage file `import s from './x.module.css'` then `s.btnPrimary` / `s['btn-primary']`, resolves the member to a class in THAT specific stylesheet (not the global registry), graded Exact, attributed to the enclosing code symbol via find_at_location. Mechanism: (1) extract_module_bindings parses default (`import s from`), namespace (`import * as s from`), and CommonJS (`const s = require(...)`) bindings → (local, specifier); named-only (`import {x} from`) and side-effect (`import './x'`) bind no local (the latter is the §11 code→stylesheet imports path). (2) keep only stylesheet specifiers (is_stylesheet_import / MIME) that are `.`-relative; map local → (normalize_join'd relpath, Language). (3) extract_member_accesses scans for `local.member` and `local['member']`/`local["member"]` via an identifier tokenizer (word-boundary; `.`-form yields JS-ident members, `[...]`-form yields any incl. kebab). (4) class_name_candidates folds camelCase↔kebab (`btnPrimary`↔`btn-primary`) so either access form resolves. (5) resolve_member_class tries each candidate via `fetch_symbol(lang.prefix(), selector_id(lang, relpath, Class, cand))`; first hit → uses_css_class edge grade Exact. Scoped to JS/TS by extension (is_js_ts: ts/tsx/js/jsx/mjs/cjs/mts/cts); non-JS files have no binding and rely on the plain token scan. Precedence over the token scan is automatic: member accesses aren't string literals, so the token scan never produced them. Still DEFERRED: 9.3 dangling-code-class. Shares the import-binding scan with §11 (code→stylesheet imports).
