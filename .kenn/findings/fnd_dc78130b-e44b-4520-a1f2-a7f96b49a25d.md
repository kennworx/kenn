The atlas has a CONTRACTS axis (build_contracts in kenn-indexer/src/atlas/producer.rs, render_contract in okf.rs, model in atlas/model.rs): first-party interfaces / base types implemented across more than one package, read STRAIGHT from the implements/extends_type aggregate edges — NOT from Louvain. Louvain is the wrong vehicle for an is-a relationship (measured across languages: it merges an arbitrary, incomplete subset of implementers, is fragile on single edges, and caps the true span); the relationship is explicit, so read it directly — complete and deterministic. It lists every first-party, non-test implementer grouped by package, each as an ID|Location row (pub_id + source location, kenn-get-able), plus the contract type's own pub_id + location. Cross-package only (MIN_CONTRACT_PKGS) — a single-package interface is the package concept's job. An empty contracts axis is itself a signal: Rust/Go keep abstractions package-local, C#/Swift spread them across the tree.
