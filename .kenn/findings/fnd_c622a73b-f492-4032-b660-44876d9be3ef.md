Markdown corpus structure reuses the code graph's MODULE primitive (design D13): one `Kind::Module` SymbolRecord per root (`md:<label>`) AND per nested directory (`md:<label>/<dir>`), deduped across files and chained `child --defined_in--> parent` up to the root (`module_chain`/`module_id` in kenn-model/id/md.rs). Each `Document`'s `enclosing_sym_id` is its directory module, with a `document --defined_in--> module` edge. IMPORTANT: the file-owning `contains` edge MOVED from the document to the directory module — `module --contains--> file` (it stays the only file-targeting edge kind); `walk_markdown` now takes the enclosing-module ShortId and no longer emits document→contains→file. Modules carry NO def (a directory is not a source span) and are minted EXPLICITLY (one per dir, always a full node) in `build_modules` BEFORE the file walk, so module ids precede file/node ids and no SCIP stub machinery is needed. Net effect: `list_in_scope("md:notes/daily")` browses a folder and `get_workspace_overview` surfaces each corpus root, all via the existing module surface with zero new MCP/reader code.
