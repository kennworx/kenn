Do NOT cache an external tool's OUTPUT (e.g. a SCIP indexer's .scip) keyed on an input set kenn enumerates itself. You cannot reliably determine a tool's inputs: an indexer reads far more than its language's source — lockfiles (Cargo.lock/go.sum/package-lock/Directory.Packages.props), resolved external dependency source/assemblies, arbitrary files pulled by include!/`//go:embed`/source-generators, and generated code. Under-hashing → a false cache hit → a silently wrong index, which is strictly worse than no cache (the failure is asymmetric: over-hashing only costs a redundant re-run; under-hashing costs correctness, invisibly). The only always-safe key is the whole source tree, which is so coarse it is near-useless — any change to any file invalidates every language's entry, and an unchanged tree is already short-circuited by git-aware staleness-skip before the cache is consulted.

Instead, cache the tool's INPUTS and let the TOOLCHAIN own invalidation: downloaded deps (CARGO_HOME/GOMODCACHE/NUGET_PACKAGES/pip/npm) and build intermediates (target/, GOCACHE). cargo checks Cargo.lock + per-crate fingerprints; incremental compilation knows exactly what to rebuild — so kenn never guesses a file set, and it is safe by construction. The indexer still runs, but warm. This is why docker-indexer-runtime dropped phase 6 (the SCIP-output cache) and kept phase 3.4 (the dependency-source + build-artifact volumes).
