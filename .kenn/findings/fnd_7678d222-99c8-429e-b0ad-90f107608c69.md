CSS `extends_rule` edges (Phase 3 §8, `css/extends.rs` + `css/ingest.rs::emit_extends_edges`): `@extend .class` (Sass) and CSS-Modules `composes` are compiled/resolved away before the browser sees them, so they are recovered by a light brace-tracking source scan (`extract_extends`) — NOT a Sass parser (see the no-own-parser directive). The scan tracks the enclosing rule via brace depth; an `extends_rule` edge (new `EdgeKind::ExtendsRule`, on-disk code 15, `EdgeProperties::ExtendsRule{grade}`, grade reuses the markdown link_grade column) is emitted from the extending class to the extended class ONLY when BOTH endpoints resolve to a known `css_class` node — a sole bare class selector on each side. Ambiguous cases (compound `.a.b`, descendant `.a .b`, `&`-nesting, interpolation, `.sass` indented syntax) yield NO edge rather than a wrong one — consistent with the usage no-dangling-stubs rule. Target resolution: `composes … from './x'` resolves the file (reusing `resolve_import`) then the exact class; same-file `composes`/`@extend` prefers a same-file def else all same-named defs (keep-all → grade Ambiguous when >1, else Exact); self-extend dropped. Runs in phase 1 (stylesheet-producer-gated, before the code barrier). `@extend %placeholder` and `@include`/mixins deferred (need placeholder/mixin kinds).
