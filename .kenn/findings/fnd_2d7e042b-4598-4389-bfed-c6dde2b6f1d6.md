USABILITY LIMITATION (deferred, surfaced dogfooding the CLI audit): 'kenn get source <id>' (get_source) for a Rust/C# symbol returns only the DECLARATION line, not the body. The stored def range is the SCIP name-token span — e.g. ServerState resolves to line 19 only ('pub struct ServerState {'), so slice_lines([start,end]) yields one line. Markdown/section symbols return their full extent because they store it. This blunts the 'vet each candidate by re-reading its source' workflow that the audit/dup/blast skills depend on — for code symbols you get the signature, never the implementation. Fix options: (a) store the full item extent (an enclosing/def-body range) at index time so def.end_line spans the body, or (b) have get_source expand to the enclosing extent / next-sibling boundary. Pre-existing, not introduced this session.
