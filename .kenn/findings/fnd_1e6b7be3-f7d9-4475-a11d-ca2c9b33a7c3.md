CRAP measurement gotchas, both of which produce confidently wrong conclusions. (1) `just crap <crate>` runs ONLY that crate tests, so functions covered by OTHER crates tests read 0% and look over-threshold when the workspace gate passes them — measured in a kenn-embed-only run: `select_backend` 56 and `SharedEmbedder::embed_with_priority` 72, neither a real offender. Per-crate CRAP is a valid proxy ONLY for functions that are genuinely 0%-covered workspace-wide; use `just crap` (no argument) before concluding a function needs work. (2) cargo-llvm-cov builds into its OWN target dir, separate from the normal one, with its own build-script output cache. A stale `cargo:rustc-link-search` there survives `cargo clean -p <crate>` against the normal target and keeps failing only under `just crap-ci`; clear it with CARGO_TARGET_DIR pointed at the llvm-cov target dir. Useful arithmetic: at 0% coverage CRAP is c^2+c, so an untestable function passes only at cyclomatic <= 5.
