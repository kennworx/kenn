The resolved toolchain version reaches the run summary as its OWN `toolchain` wire frame, NOT a MetaFrame field: the kenn-toolchain ENTRYPOINT execs a SEPARATE indexer process, so it cannot add to the indexer's own meta frame. Path: kenn-toolchain emits {type:toolchain,language,version} to stdout before exec -> kenn-indexer parse_jsonl::ToolchainFrame -> JsonlIngestStats.toolchains -> RunReport.toolchains -> SnapshotMeta.toolchains -> render_toolchains (overview.md + kenn status). Emit ONLY for the JSONL-wire languages (C#/TS/Swift): a VALID frame on their stdout is legitimate wire data, not the 'stray byte' the no-stdout-writes rule bars — that rule stands for garbage, not frames. SCIP producers (rust/go/python/node) write a .scip file, so their stdout is NOT the data wire; they get NO frame (it would be lost) and need a separate provenance channel, not yet built. This is diagnostic provenance, NOT a staleness input (pin files are already tracked, so the staleness key covers pin edits).
