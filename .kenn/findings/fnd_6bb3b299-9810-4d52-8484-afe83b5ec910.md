kenn init --docker default images are DIGEST-PINNED manifest-list refs, held as the IMG_* consts in crates/kenn-cli/src/init/detect.rs and threaded onto LanguageSpec.default_image. NAMING: images are named by LANGUAGE — ghcr.io/kennworx/kenn-<lang> matching kenn's [language.X] config keys (kenn-rust, kenn-go, kenn-python, kenn-typescript, kenn-csharp, kenn-swift); keep this uniform when adding a language, and mirror it in .github/workflows/images.yml + the docker/kenn-<lang> build-context dirs + the justfile build-image cases. Docker is a FALLBACK: init only containerizes a detected language whose local toolchain probe fails, and only with a runnable daemon. Digests go STALE when images.yml republishes — refresh each with 'docker buildx imagetools inspect ghcr.io/kennworx/kenn-<lang>:latest' (top-level manifest-list digest, not a per-arch child). To rename/copy an image WITHOUT rebuilding, 'crane copy src dst' does a registry blob-mount that preserves the digest. GHCR container-package visibility is web-UI only (no REST API); package DELETE needs the delete:packages token scope.
