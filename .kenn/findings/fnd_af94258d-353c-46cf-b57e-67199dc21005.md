The markdown ingest must populate the per-unit `RunReport` counts (`files_seen`/`symbols_seen`/`defs_seen`/`edges_seen`) — the CLI's `aggregate_counts` sums them into the snapshot `meta` (what `kenn status` shows) AND into `compute_regressions` (the count-drop guard). A markdown unit that leaves them 0 makes `kenn status` report 0 docs/symbols/edges for a markdown corpus and makes regression detection blind to markdown (it never fires). Fix: `ingest_markdown_phase1` and `resolve_markdown_code` return a `MarkdownCounts` accumulated as records are pushed (modules+nodes+stubs for symbols, defs, contains/defined_in/links_* for edges), and the pipeline's `markdown_phase1_unit` / `resolve_markdown_code_unit` copy them onto the report. Separately: any "no languages enabled" guard in `cmd_index` MUST include `config.language.markdown.enabled`, or a markdown-only config prints a misleading "nothing to index". Note these report counts are record-push counts and may differ slightly from the finalized DB counts (same report-vs-DB nature as the code path) — that's expected, not a bug.
