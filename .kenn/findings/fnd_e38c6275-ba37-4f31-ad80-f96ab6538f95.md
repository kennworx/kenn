index.md groups packages by ROLE in the dependency graph, not by language. Language is a filesystem fact and it collapses at scale: a real 125-package solution rendered as 123 alphabetical bullets under one heading, telling a reader nothing about which packages matter. Sections run foundation-first — Providers, Layers, Consumers, then Tests and Isolated last (on that solution tests were 36 of 125 packages and none of its architecture; Isolated means no cross-package coupling either way, i.e. vendored, dead, or unwired, which a flat list hides completely). Within a section the most-depended-on package leads, never alphabetical.

Role comes from ONE number: instability I = out/(out+in) over aggregate-edge weight, quartile thresholds (I <= 0.25 provider, >= 0.75 consumer). Deliberately not a finer taxonomy — separating adapter from engine, or vocabulary from contract, needs axes measured to have almost no dynamic range (abstractness was 0% for 8 of 15 packages on one repo), and a confident wrong label in a bird's-eye view is worse than a number. TWO ORDERING RULES ARE LOAD-BEARING in classify(): test-dominance is checked FIRST (a test package is not load-bearing architecture whatever its coupling looks like), and zero-coupling is checked BEFORE the ratio — instability is UNDEFINED there, not zero, so falling through would file an isolated package as a Provider, the exact opposite of the truth.

Every entry carries the counts the label came from — `(N used by · M deps)`, plus the language when the repo is multi-language, since role sections replaced the per-language ones. That is the point: the classification is auditable, not asserted. Roles are computed over the FULL coupling sets, never the capped render rows, so a display cap can never move a package between sections.
