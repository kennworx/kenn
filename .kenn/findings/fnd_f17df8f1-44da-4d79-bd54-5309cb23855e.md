Index the format, never a catalogue of things the author happened to know. A producer must not recognize, name, or special-case any third-party framework's element names, attribute names, or namespace URIs — nor any specific database's internal object names. kenn analyses SQL; it does not model a database. Concretely: do NOT filter, hide, or reclassify pg_catalog / information_schema / pg_* tables in the SQL extractor. Measured on a real C#/TypeScript workspace, 22 of 59 tables were Postgres system catalogs — and they are TRUE references: the code really does query them. Suppressing them would mean (a) carrying one vendor's internal names inside a module whose whole contract is 'SQL text in, references out', (b) being wrong for the other 13 dialects in the sweep, (c) drifting with every server version, and (d) reporting a falsehood about what the code reads. A caller that wants to hide them can filter on the name it already has; that is a presentation choice, not an indexing one. The same rule is why the XML producer ships mechanism and takes any vocabulary as configuration. Format-level identity carriers (an 'id' or 'name' attribute; sqlparser's own ObjectType) are properties of the format, not of a vendor, and are fair game.
