Verifying a refactor by RE-INDEXING kenn own repo is invalid — kenn indexes its own source, so editing the indexer changes the graph the check reads. A behavior-preserving atlas/graph refactor looked like a regression this way: the domains diff was full of symbols from the very files the refactor added. Verify on an UNCHANGED external repo instead: build the old binary, index a repo under ./tmp with it, restore, rebuild, re-index the same repo, diff the bundle. That is what proved the domains/contracts rule extraction byte-identical.

Second trap on the same path: a real repo may be non-deterministic run-to-run, so a diff alone cannot tell "my change broke it" from "it was never stable". ALWAYS run the OLD binary twice on the same unchanged repo first and diff old-vs-old.

SUPERSEDES the previous claim that Swift is unstable — that is FIXED (2026-07-26). The cause was the Swift emitter iterating a Dictionary and a Set whose order reached the wire, and Swift reseeds its hasher per process; see the Swift-determinism directive. Two full pipeline runs over an unchanged Swift repo now differ only in the atlas header timestamp, so Swift is a valid substrate for producer-vs-query parity and old-vs-new diffs. `just swift-determinism` asserts it. Go remains deterministic too.

The general rule survives the fix: before trusting ANY old-vs-new bundle diff, establish the baseline is stable by diffing old-vs-old. Determinism is a property to verify per language, not to assume — and a same-snapshot producer-vs-query parity check is stable even where cross-run diffs are not, because both sides read one snapshot.
