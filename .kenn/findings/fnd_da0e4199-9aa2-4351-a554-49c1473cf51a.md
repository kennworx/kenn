Every in-house indexer sidecar (kenn-dotnet, kenn-ts, kenn-swift) MUST answer `--version` with a bare version on stdout, exit 0, and no toolchain loaded. `kenn init` probes each indexer this way to decide whether the language is indexable; a non-zero exit silently degrades that language to the generic text fallback, with no symbol graph and no error. The probe must never require the toolchain it is probing.

Each has failed this differently: kenn-dotnet registered MSBuild before parsing argv; kenn-ts's node:util parseArgs is strict and threw ERR_PARSE_ARGS_UNKNOWN_OPTION as a raw TypeError against bundled source; kenn-swift's option loop had `default: break`, so `kenn-swift index --version` discarded the flag and started a full workspace build.

Corollaries: an unknown option is a usage error (exit 2 on stderr), never an uncaught throw; an option's value must not be the next token when that token is itself an option; and the version must have one source (kenn-dotnet reads AssemblyInformationalVersion, kenn-ts imports package.json) so `--version` and the wire's tool_version cannot drift. The contract is verified by `just probe-smoke` against the built binaries in ./build, and `just test-indexers` runs it.
