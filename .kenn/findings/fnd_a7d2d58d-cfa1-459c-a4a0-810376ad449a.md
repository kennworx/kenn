A property enforced at MORE THAN ONE site cannot be mutation-checked by mutating one site. CLAUDE.md section 9 says break the code and watch the test go red; the trap is that redundant guards each keep the test green, so a single-site mutation "proves" a guard that is really carrying nothing on its own.

Found live: the atlas producer excludes example nodes TWICE in the same loop — an early `if n.example { continue; }`, and the `example` fact handed to `domains::is_domain_eligible`. Neutering either alone left the test passing. Only neutering both rendered the phantom domain. Had the check stopped at the first mutation, the recorded claim ("dropping this guard renders a domain") would have been false, and a later refactor deleting the OTHER site would have shipped silently.

So: when a mutation does NOT turn the test red, that is a finding, not a nuisance — the property is enforced elsewhere. Find the second site before concluding anything, then record the CONJUNCTION in the test doc rather than naming one site. And keep the redundancy only when each site earns it independently (here the early `continue` also keeps example code out of the package central list, so it is not dead).
