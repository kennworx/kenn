Why the kenn-dotnet no-SDK invariant cannot be tested from the xunit suite, and lives in `just probe-smoke` instead.

Under `dotnet test`, kenn-dotnet runs via `dotnet exec`. MSBuildLocator discovers .NET Core toolsets from the running host's `Environment.ProcessPath` — the muxer — not only from env vars. Scrubbing PATH, DOTNET_ROOT, DOTNET_HOST_PATH and DOTNET_MSBUILD_SDK_RESOLVER_CLI_DIR does NOT make registration fail: verified, `env -i PATH= dotnet kenn-dotnet.dll index` still registers MSBuild successfully. Only the self-contained single-file binary (which the test suite never builds) has a ProcessPath that resolves nothing, and `env -i PATH= ./build/kenn-dotnet --version` is therefore the only honest probe.

A test spawning the DLL with a scrubbed environment looks behavioral and passes with the regression re-injected. What xunit CAN honestly assert: the NoInlining attribute on IndexCommand.Run (reflection), the version's single source, and ToAscii/FormatReason degradation of an OS-localized exception message.
