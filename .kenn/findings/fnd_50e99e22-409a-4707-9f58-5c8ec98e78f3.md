On-demand toolchain provisioning: the SHAPE. This SUPERSEDES the 'images are FROM scratch, toolchains provisioned HOST-SIDE in Rust' direction — the rule it enforced still holds, the mechanism does not.

THE RULE (unchanged): what the WORKSPACE pins is provisioned; what the INDEXER needs is payload. A repo declares its toolchain (global.json, rust-toolchain.toml, go.mod, .python-version, Package.swift) and that version is fetched at index time into a shared cache volume. Baking one means image and repo can disagree, and that failure is SILENT — zero files, exit 0.

THE MECHANISM (revised): images are NOT scratch. Each is ubuntu:noble and runs kenn-toolchain as ENTRYPOINT; that binary reads the pin, provisions into /kenn-toolchains, prepends PATH, and execs the real indexer. Provisioning happens INSIDE the container, not host-side — the user's constraint was 'all downloads shall be done in docker; only call docker in rust to build docker images'. Scratch was abandoned because a scratch image has no CA bundle, no shell, and no way to run an installer, and because every download then had to cross back to the host.

SWIFT IS THE ONE EXCEPTION and it is not a wart: swift.org publishes no verifiable download (a URL and a detached PGP signature, no machine-readable checksum), so kenn copies the toolchain out of the official swift:<tag> image, where content is digest-addressed and every layer is verified on pull. That needs a docker daemon, so it runs on the HOST during preflight; the entrypoint then finds the toolchain already in the volume (Install::Preprovisioned) and only does the PATH-and-exec half.

TWO CONSTRAINTS THAT ARE EASY TO BREAK, both cost a full debugging cycle:
1. NOTHING may write to stdout — it is the JSONL wire. kenn-ts had to force the TypeScript compiler's traceResolution off; a single trace line is a line-1 parse error.
2. The entrypoint EXECs, it does not spawn-and-wait. As PID 1 a spawning parent never reaps orphaned grandchildren, so indexers that shell out (go list, dotnet restore) fail while still reporting success. Go went from 195 bytes of output to 283,441 on that one change, after three wrong diagnoses.
