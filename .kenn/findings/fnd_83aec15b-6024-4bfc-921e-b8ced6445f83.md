Atlas package coupling is rendered in BOTH directions, typed and weighted, from ONE pair map. producer.rs builds pair_w keyed (src_anchor, dst_anchor) -> relation -> weight; '## Depends on' filters on the source and '## Used by' on the target, so the inverse can never drift from the forward view. 'Used by' renders FIRST: a reader about to change a package wants its blast radius, and the outgoing list cannot answer it — before this, a package four others depended on rendered a concept naming only what IT depended on. The weight was always computed (it ranks the list) and always discarded at render; keeping it plus the relation split is what turns 'kenn-store depends on kenn-model' into 'depends on it 2007 times, almost all type references'. The split earns its column mainly through 'implements', which marks a contract/implementer pair no weight sum can express — on a real Go repo afero/mem shows up under afero's Used by with 'implements 16' and NOTHING else, which reads as 'this package exists to implement those interfaces'. Two invariants: an empty direction renders NO heading (a vocabulary package has no dependencies, a leaf none depending on it — an empty table is noise); and Coupling carries the target's display title alongside its concept id, because the id's leaf is the flattened language-prefixed filename ('rust_kenn-config'), not a name anyone types. Component and document concepts carry no couplings at all — a component is a slice of one package, and a document participates in no package graph.
