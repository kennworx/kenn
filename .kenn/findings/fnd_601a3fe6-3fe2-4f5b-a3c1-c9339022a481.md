Table identity is order- and knowledge-dependent, so ANY change that adds declarations can silently re-attribute unrelated tables. sql::registry::resolve treats a schema-qualified reference and a bare one as different identities that never unify: a qualified ref always mints 'schema.name' without consulting the registry, while a bare ref resolves against identities_named(name) and mints 'name' only when nothing is known. Because 'known' is built from what the earlier passes wrote, growing it flips bare refs onto a qualified identity. Measured: enabling DDL recovery on a partial parse moved a Liquibase-declared table from 'sql:<name>' (internal, one declares) to 'sql:<schema>.<name>' (external, one modifies) on a real corpus, with no code path between the two changes. So when evaluating any indexing change, do NOT read the internal/external census as a stable before/after — diff per identity (pub_id), not per name, or a pure addition will look like a regression and a real regression will hide.
