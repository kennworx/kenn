MCP tools that list a potentially-unbounded result set MUST bound their output, not return everything: cap the rows at a `limit` (clamped default/max), report the full matching `total` and a `truncated` flag so the caller knows there's more, and offer a filter argument to narrow. Example: `check_links` (kenn-mcp/src/tools/links.rs) takes `grade` (drifted|fuzzy|ambiguous|dangling, unknown name → loud InvalidInput) + `limit` (default 100, max 1000); the store query `scan_link_diagnostics(grade_codes, limit)` pushes the grade filter + `LIMIT` into SQL and runs a separate `COUNT(*)` for the true total, so a rotted 10k-doc corpus (5k+ broken links) can't flood the response or balloon reader memory. This complements the latency-budget directive: bounding result SIZE matters as much as bounding latency for keeping agents on kenn instead of falling back to shell.
