A paginated verb must not claim "every" in its help text, and every axis verb must page the same way. `kenn packages` was the only one of the four axis verbs without `--page-size`/`--cursor`/`--all`, so an agent that learned the pattern from `kenn domains` found it missing exactly where it matters most — a 125-package solution.

Two things this surfaced that are worth keeping:

PAGE BEFORE ENRICHING. `list_packages` costs a `fetch_symbol` per row to verify the root pub_id, plus a possible symbols scan for the C# namespace fallback and a def/doc scan for metadata. Paging at the END would run all of that for 125 packages to return 25. Page straight after the pure `package_views` projection, then enrich only the page. Safe because `package_views` already orders deterministically (most-depended-on first), which is what makes an offset walk sound.

THE HELP TEXT WAS ALREADY LYING. All four verbs said "Bare: every package/domain/contract ..." while bare has always returned the DEFAULT_PAGE of 25 with a `next` cursor — I introduced that inaccuracy for three verbs when adding pagination and extended it to the fourth. Adding a flag silently changes what the bare invocation means; re-read the doc comment as part of the change, not after someone trusts it. All four now say "the first page ... pass `--all` for every one".

Related: name the ESCAPE, not just the limit. A capped atlas heading now reads `## Domains — 78, heaviest 24 shown · all via `kenn domains``. Admitting truncation without saying how to see the rest leaves a reader with 54 invisible domains and nowhere to go.
