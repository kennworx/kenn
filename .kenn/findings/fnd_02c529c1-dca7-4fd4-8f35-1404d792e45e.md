Swift build caching via `--scratch-path`/`--build-path` (task #42) is BLOCKED on Swift 6.3.3 (Apple swiftlang-6.3.3): `swift build --experimental-prepare-for-indexing --scratch-path <dir>` fails with `chdir error: No such file or directory: <packageDir>` (same for --build-path, and for a scratch dir literally named .build), and the failed prepare run poisons the plain-build fallback so the index store loses `calls` relations. Plain `swift build --scratch-path` alone works (calls present), but kenn-swift REQUIRES prepare-for-indexing for error-tolerance — indexing non-compiling packages (testNonCompilingPackageIsFullyIndexed). So the .build scratch-redirect design in runSwiftBuild (Provisioning.swift) is non-viable with the current prepare-first build strategy. Options: (a) defer until the toolchain fixes prepare-for-indexing + custom scratch path; (b) flip to plain-build-primary + prepare-for-indexing-fallback-WITHOUT-scratch (compiling packages get cached stores with calls; broken packages fall back uncached). Do NOT add --scratch-path to the prepare-for-indexing invocation.
