GOTCHA (fixed): the findings staleness resolver must key on the `pub_id` column directly, NOT `format!("{language}:{pub_id}")`. `pub_id` already carries the language short-code (`cs:`, `rs:`, `ts:`) — it IS the canonical code-node id that find_symbol returns and that findings store as parent_ids. A prior bug concatenated the `language` column (`csharp`/`rust`) onto it, producing doubled ids (`csharp:cs:Foo`) that never matched, so finding_is_stale returned true for EVERY code-cited finding, in every language — silently making the `stale` flag (search_findings / find_directives / semantic_search) non-functional repo-wide. Unit tests missed it because they used MOCK resolvers; the real SQL-backed resolver was never exercised against real pub_ids. Found by dogfooding the reconcile skill on a large external C# repo (~71k symbols).
