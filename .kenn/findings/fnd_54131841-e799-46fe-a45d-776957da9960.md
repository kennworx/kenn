CSS-internal `imports` graph (Phase 3 §8, `css/internal.rs` + `css/ingest.rs`): `@use`/`@import`/`@forward` are recovered by a light source scan (`extract_imports`) and become `imports` edges (reusing `EdgeKind::Imports`) between stylesheet `module` nodes. CRITICAL (found via real-world test on Bootstrap, fixed): EVERY discovered sass file must get a `module` node, not just those that contribute selectors — because the common barrel/entry pattern (`bootstrap.scss`/`bulma.scss` are pure `@import`/`@forward` with no selectors of their own) would otherwise have no module and emit zero import edges. `ingest_sass` compiles entries (non-`_`) then calls `acc.ensure_module(relpath)` for ALL discovered sass files (incl. import-only barrels and functions-only partials); `.css` always gets a module via `parse_css`. Resolution (`resolve_import`) applies Sass rules (bare→`_name.scss` partial, index files, extensions); missing target → no edge. Runs inside phase 1 (stylesheet-producer-gated, not the code barrier). Validated end-to-end via `kenn index`: open-props 1950 css nodes; Bootstrap 928 classes/576 vars/99 modules/144 imports (generated classes like `bg-opacity-25` present); Bulma (modern @use/@forward) 2288 classes/2421 vars/272 imports. Deferred: `@extend`/`composes` (`extends_rule`) + `check_css` (§9).
