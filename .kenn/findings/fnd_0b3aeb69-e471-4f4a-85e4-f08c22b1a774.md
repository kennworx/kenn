kenn-mcp tool handlers MUST NOT block indefinitely or exceed a small latency budget. Every MCP tool returns well under ~200ms on a Ready server (or with a fast error), EXCEPT `wait_for_index`, whose blocking is bounded by its own timeout (default 30s, cap 120s). Concretely: never hold a lock across a slow/unbounded `.await` (findings reads should use a shared read lock, not an exclusive Mutex); never block a runtime worker on synchronous I/O that can exceed the budget (offload blocking SQLite leaves like connect()/count_table); surface a degraded subsystem as a fast retryable error (e.g. EMBEDDER_STARTING) rather than an unbounded wait. A hung tool makes agents abandon kenn and fall back to shell. Diagnosis aid: the server should log every tool call with name + duration so a stall is greppable, not requiring a process sample.
