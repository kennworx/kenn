Verify a cross-language graph feature on ONE REAL REPO PER LANGUAGE, and pick each repo for the FEATURE, not just the language — a repo lacking the thing under test yields a null case that proves only "nothing broke". Persisting the example-path provenance flag looked fully verified on this Rust workspace; the per-language sweep is what actually settled it, and two of the six results were only reachable there.

C# (a 125-package solution) flagged ZERO nodes, which looked like a broken def->file join and was not: its five files matching %sample%/%fixture% carry the word in the FILENAME (Samples.cs, AspNetFixture.cs), and is_example_path matches whole SEGMENTS. A substring rule would have silently dropped five production types out of the domain axis. Its real examples/*.cs sit in vendored projects the solution never references, so they are never indexed — the zero is honest twice over.

Swift symbol names are NOT filename-safe: `replacing(_:with:)` is stored as `replacing-_-with.md`, so comparing atlas FILENAMES against query TITLES reports a false divergence on Swift alone. Compare the `title:` front-matter field inside the concept doc. This is a slug mapping, distinct from the known Swift symbol-id run-to-run instability (fnd_ffc03393) — a same-snapshot producer-vs-query check is stable on Swift.

SCALE is a test dimension of its own. Only the 125-package repo has more than MAX_DOMAINS (24) domains, and it is the only one that exposed the atlas summary reporting 24 when the repo has 78. Every small repo passes a cap bug silently. Keep at least one genuinely large repo in the sweep.
