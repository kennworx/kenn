Native single-file publish of kenn-dotnet (self-contained, -r <rid>) MUST set IncludeAllContentForSelfExtract=true. Roslyn 5.6's MSBuildWorkspace evaluates projects in an out-of-process BuildHost child (BuildHost-netcore/*.dll + its .deps.json/.runtimeconfig.json); the plain single-file bundler EXCLUDES those config files (NETSDK1236) so the child can't launch. IncludeAllContentForSelfExtract bundles ALL content into the one file and self-extracts it to ~/.net (or DOTNET_BUNDLE_EXTRACT_BASE_DIR) at startup, where Roslyn locates + launches the BuildHost. Verified: the LONE binary (no co-located BuildHost dirs) indexes a net10 project. There is no supported 'force in-process' toggle in Roslyn 5.x. The docker image publishes framework-dependent (no single-file) so it is unaffected.
