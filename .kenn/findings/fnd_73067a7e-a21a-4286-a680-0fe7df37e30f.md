GoTransformer (`id/go.rs` `scip_to_public`): build the `go:` public id from the DESCRIPTOR segments alone — do NOT prepend `head.package`. In a scip-go symbol `scip-go gomod <module> <ver> <descriptor>`, the descriptor's first `Namespace` segment is the FULL package import path (`obj.Pkg().Path()`, backtick-escaped when it contains `/` or `.`), while the `head.package` field is the MODULE path — and the two genuinely differ (scip-go's own composer_test.go:154: module `example.com/project`, package `example.com/lib`; for stdlib the module is `github.com/golang/go/src` and the package is just `context`). Prepending the module DUPLICATES the package path for first-party symbols (`go:…/conc/…/conc/pool.Pool`) and emits the wrong package when module≠package. Correct: descriptor namespace = package path, types/terms/methods appended with `.`; module/version is metadata, not part of the id. Verified against scip-go 0.2.4 on conc + helm (0 duplicated-package ids).
