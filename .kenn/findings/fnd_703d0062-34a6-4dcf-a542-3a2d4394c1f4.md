kenn's SCIP edge pipeline was silently coupled to scip-python/scip-typescript's NON-standard occurrence conventions; a spec-following indexer (scip-go) exposed three latent bugs that produced ~0 useful edges (helm: 682 edges for 5,592 symbols → 41,577 after fixing all three). When adding/validating any SCIP indexer, check these: (1) FROM-attribution — `DocumentDefIndex::from_document` in edge.rs must index each definition by its `enclosing_range` (the BODY), falling back to `range` (the NAME) only when absent/malformed. A reference is contained by the function body, NEVER by the bare name identifier. scip-go (per the SCIP spec) puts `enclosing_range` only on DEFINITIONS, never on reference occurrences; scip-python stamps it on references, which is why name-range indexing happened to limp along for it. (2) Edge KIND — scip-go tags EVERY reference `ReadAccess`, so `classify_edge_kind` must derive the kind from the TARGET DESCRIPTOR (`().`→call via TypeUse+refine, `#`→type_use, plain `.`-term→field_access), not from the role; keying off ReadAccess collapses everything to field_access. (3) External-symbol stubs — `build_stub_from_scip` in transform/naming.rs must run the symbol through `transformer_for(lang).scip_to_public` to get the canonical `go:`/`rs:` pub_id; storing the raw descriptor leaves genuine externals (stdlib/deps, referenced-but-never-defined) with malformed ids like `context/Background().`. All three fixes are language-agnostic and strictly more correct.
