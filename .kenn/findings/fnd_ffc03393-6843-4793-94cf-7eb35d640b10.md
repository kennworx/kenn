Verifying a refactor by RE-INDEXING kenn's own repo is invalid — kenn indexes its own source, so editing the indexer changes the graph the check reads. A behavior-preserving atlas/graph refactor looked like a regression this way: the domains diff was full of symbols from the very files the refactor added (ShortId, kenn-indexer members). Verify on an UNCHANGED external repo instead: build the old binary (git stash), index a repo under ./tmp with it, restore, rebuild, re-index the same repo, diff the bundle. That is what proved the domains/contracts rule extraction byte-identical.

Second trap on the same path: a real repo may be non-deterministic run-to-run, so a diff alone cannot tell 'my change broke it' from 'it was never stable'. ALWAYS run the OLD binary twice on the same unchanged repo first and diff old-vs-old. Swift is currently unstable this way — the same 5 domain docs differ between two runs of one binary because symbol-id disambiguation suffixes (#b0c7df etc.) get reassigned, which also means any producer-vs-query parity test will be flaky on Swift until that is fixed. Go is deterministic and is the reliable substrate for this check.
