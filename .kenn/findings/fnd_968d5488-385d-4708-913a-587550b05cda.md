kenn-ts names an IN-WORKSPACE project by its DIRECTORY relative to the workspace root, NOT its package.json `name` (indexers/kenn-ts/src/indexing/packages.ts). In a monorepo the directory is the project identity; an npm `name` is often a product name or a boilerplate/starter-kit template name that misleads or even collides with the workspace name (which then produces a bogus package concept titled like the whole repo). An EXTERNAL dependency (node_modules / out-of-workspace) keeps its npm name — imports resolve to it by that name. This drives the atlas package/anchor title for TS.
