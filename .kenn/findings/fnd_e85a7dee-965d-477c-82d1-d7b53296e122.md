`RunReport.indexer_version` is seeded `"?"` by every driver, because a driver cannot know its producer's version until the producer speaks. Set it where the producer identifies itself, not by carrying it through `UnitCounts` into `finalize_unit`:

- SCIP: `absorb_scip_metadata` captures `Metadata.tool_info.version` into a local `Option<String>`; `apply_observed_version` writes it to the report BEFORE the `?` on the parse result, so a stream that fails midway keeps the version it already reported. The failing unit's report is the one a human reads.
- JSONL: `ingest_jsonl_subprocess` copies `stats.tool_version` (captured in `handle_frame`'s Meta arm) onto the report as soon as ingest returns.
- In-process producers (markdown/css/html/text) report `IN_PROCESS_PRODUCER_VERSION = env!("CARGO_PKG_VERSION")`. They previously passed a bare "0", which sat next to real versions in a mixed report and read as one.

Carrying it via `UnitCounts` looks tidier and is worse: it forces `finalize_unit` to `pub(crate)` for a test, loses the version on the Err arm, and puts the assignment one layer away from anything a test can assert. Both paths live in kenn-indexer's pipeline, so the CLI and MCP orchestrations get the fix from one source (see fnd_43521e99).
