A language's docker caches are INDEPENDENTLY optional. LangCache holds 'source: Option<SourceCache>' and 'build: Option<BuildCache>' as SIBLINGS, and docker_launcher wires each on its own. They were once nested — 'build' hung off a present 'source', and workflow.rs built the whole thing with 'source.map(...)' — so Swift, which wants a BUILD cache and no source cache (SwiftPM keeps its checkouts under '.build', so redirecting that one directory covers both), silently got NEITHER: KENN_SWIFT_SCRATCH was never set and the per-worktree build volume never mounted, leaving SwiftPM writing to the slow host bind mount on every run while the surrounding code and comments read as though the feature worked. Dead wiring like this is invisible from the call site — when adding a build-only or source-only language, assert the env var AND the volume mount in a docker_launcher unit test.
