cmd_index::run_async (CLI 'kenn index') and workflow::index_workspace (workflow/MCP) are PARALLEL orchestrations of ONE index run: begin -> build_workspace -> configure_runner -> open_writer -> run_pipeline -> persist artifacts -> publish. Every shared step must go through a single-source helper in kenn-indexer or it silently drifts between the CLI and MCP paths. This has bitten repeatedly: markdown + dotnet test_globs dropped from the workflow's configure_runner; Swift excludes dropped from the workflow's workspace builder; meta.json 'status' hardcoded to 'success' on the MCP path, hiding partial-failure runs. Unified so far (single-source in kenn-indexer): build_workspace, configure_runner, and the report helpers aggregate_status / collect_failed_projects / render_overview_md (report.rs). Do NOT reintroduce a per-path copy of any of these. STILL duplicated (follow-up): the persist-artifacts orchestration itself + SnapshotMeta, which lives in kenn-cli/cmd_status.rs where kenn-indexer can't reach it; relocating SnapshotMeta to a shared crate would let one writer serve both paths. Regression tests: crates/kenn-indexer/tests/{markdown_producer_parity,build_workspace_parity,meta_status_parity}.rs.
