kenn-dotnet flags a C# project as test code (all its symbols emit test=true) when ANY holds, checked in a race-free pre-pass (MarkTestProjects) before the parallel walk: (a) its csproj declares <IsTestProject>true> OR a test-framework <PackageReference> (xunit/nunit/mstest/Microsoft.NET.Test.Sdk); (b) a <ProjectReference>, followed ONE level, points to a project whose csproj carries a test framework (a shared test-helper/base that references e.g. nunit); (c) its assembly name matches a configured [tests] assembly_regex; or (d) resolved project.MetadataReferences include a test-framework assembly.

CRITICAL: signals (a)/(b) READ THE CSPROJ XML (XmlDeclaresTest / XmlReferencesTestFramework over doc.Descendants), not resolved references — under central package management + --skip-restore, NuGet assemblies never resolve into project.MetadataReferences, so the reference check (d) silently misses genuine test projects. Real miss this supersedes: a *.Tests project with <IsTestProject>true> and a versionless <PackageReference Include="nunit"> came out untagged. Still do NOT use Microsoft.Build LoadProject to read the IsTestProject property — the csproj XML read is the cheap restore-independent alternative (LoadProject is a full second SDK evaluation per project).

Invariants: prefer declaration-based detection over assembly-name matching — a name regex both false-positives (a production app that merely has "Test" in its name) and misses plural .Tests. <IsTestProject> is a self-marker, NOT contagious across a ProjectReference; a test-framework reference IS contagious. csproj matching spans ALL ItemGroups (doc.Descendants, incl. conditional), matches PackageReference Include= (not Update= / PackageVersion), splits MSBuild ;-lists, and normalizes \ separators. Per-pass results are memoized (CsprojTestInfo: SelfDeclares/ReferencesFramework/ProjectRefs) so each csproj is parsed once. Config flows [tests] assembly_regex -> kenn-dotnet driver -> --test-assembly-regex.
