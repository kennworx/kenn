A TypeScript monorepo reference resolves into the OTHER package's build output, and must be keyed back to source. Package b importing package a resolves through a's package.json 'types' field to a/dist/index.d.ts — a different file from a/src/index.ts, so it gets a different symbol key, matches nothing indexed, and lands as an EXTERNAL stub. Measured on a real 3-package monorepo: 65 symbol pairs / 156 weight of server->core references sat in the same bucket as @types/react and zod, and the first-party package graph had ZERO cross-package edges. OutDirMap (indexers/kenn-ts/src/indexing/outdir.ts) inverts it: <outDir>/p.d.ts -> <rootDir>/p.ts. The mapping is DERIVED from the package's own tsconfig (outDir + rootDir are declared), never guessed — verified 19/19 exact on that repo — and is required only when declarationMap is off, which is the common case (that repo sets declaration: true, declarationMap: null). Two properties are load-bearing: the remap is applied to the PATH before keying, and isExternalPath judges that path, so a remapped declaration is treated as its source while a hand-written first-party .d.ts (nothing remapped it) keeps its external treatment; and the remapped path is only a CANDIDATE — ensureRef links solely when that key was already emitted as a full symbol, so a mapping with no indexed counterpart degrades to no edge, never to a wrong one. Do NOT 'fix' this by indexing dist/: the built declarations are 1:1 with src (26 vs 27 files there), so it would double the TS symbol surface and make every public type appear twice.
