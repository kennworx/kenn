CSS and Sass are modeled as TWO `Language` variants (`css` for `.css`, `sass` for `.scss`/`.sass` — one Sass language, two syntaxes) but share ONE set of node kinds (`Kind::CssClass`/`CssId`/`CssVar`) and ONE class registry. The split is source-provenance only (drives prefix/db_name/extensions/partitions/filtering); it must NOT become per-language kinds, and it must NOT be collapsed into a single `Language::Css` (a `.scss` file tagged `css` is dishonest — Sass is a compiled superset, and the two processing paths fall on exactly that boundary). The config is also unified: one `CssConfig` (`[language.css]`) covers both, with Sass-only knobs in a nested `sass` subsection. "All stylesheet classes" is a query by kind, not language.
