LESSON (dogfooding 2026-06-24): running kenn's own skills (reconcile, audit, dup) end-to-end against a real large external repo (~71k symbols, freshly indexed) found 4 real bugs in ONE session — and every one was structurally invisible to the existing test suite. All 4 were in the NEWER embedding/drift/staleness plumbing; ZERO were in the mature code-graph navigation (blast/trace needed no fixes). Each bug hid behind a specific test blind spot: (1) staleness resolver used MOCK resolvers in tests, never the real SQL one; (2) cold-embedder degrade — tests always had a warm embedder; (3) deletion-staleness — fixtures never deleted a tracked file; (4) find_similar silent-empty — test corpora were always embedded. Takeaway: for the knowledge/vector layer specifically, unit tests with mocks/fixtures give false confidence — integration-test against a really-indexed AND really-embedded repo, and run the skills expecting CONCRETE real outcomes (stale:false here, neighbors there). The bugs surfaced precisely because the dogfood expected a specific result and got a wrong one. The graph-navigation layer, by contrast, is mature and held up under the same pressure.
