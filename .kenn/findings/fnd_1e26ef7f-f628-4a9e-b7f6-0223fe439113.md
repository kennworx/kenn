kenn's `get source` returns the WHOLE item (doc comment / attributes through the closing brace), sliced from a STORED body extent (defs.body_start_line/body_end_line), never parsed at query time. The extent is CAPTURED from what each producer already computes: SCIP `Occurrence.enclosing_range` (rust-analyzer >= Dec-2025, scip-go, scip-python) in transform/document/walk.rs, and the full declaration-node span in the C#/TS JSONL producers (kenn-dotnet RangeUtil.FromSyntaxNode, kenn-ts rangeOf(sf, decl)). It is stored lines-only (get_source slices whole lines) and kept DISTINCT from the name span (start_line/end_line), which find_at_location + edge anchoring still use. Lesson: when a value is already computed upstream (here enclosing_range, which DocumentDefIndex reads for edge FROM-attribution then discarded), thread it through to storage — do NOT re-derive it with a query-time parser. A brace scanner was rejected (wrong for Python: indentation, not braces) and tree-sitter was disproportionate. rust-analyzer's enclosing_range is version-gated: the rustup-bundled build lags the standalone release; on a pre-Dec-2025 build get_source falls back to the declaration line and kenn warns (cmd_index: a Rust unit with defs_seen>0 but def_bodies_seen==0). Use a Dec-2025+ rust-analyzer (Homebrew rust-analyzer, or a current rustup).
