The TypeScript outDir remap only fires for PLAIN-TSC packages, and that is a boundary of the feature, not a gap in it. `OutDirMap` forms a pair only when a package tsconfig declares BOTH `outDir` and `rootDir` (kenn-ts core.ts: "both or neither — without a declared rootDir there is no inverse"), and the remap only matters when the package `types` field resolves INTO that same outDir. Screened four real packages:

- understory/core — outDir=dist, rootDir=src, types=./dist/index.d.ts → MATCH. Verified end-to-end: 0 first-party symbols keyed under dist/, 37 first-party edges server→core. Without the remap those 37 are external stubs.
- TanStack react-table and table-core — no outDir, no rootDir. types points at ./dist, which vite produces.
- nestjs common — no outDir at all; tsc emits declarations IN PLACE beside the sources.

The pattern: bundler-built packages (vite, tsup, rollup) generate declarations with a separate tool into a directory tsconfig never mentions, so no pair forms and the remap cannot apply however many extensions it knows. Plain-tsc publishable packages are the ones it serves.

Consequence for coverage: the `.tsx` arm of the remap (`Button.d.ts` may come from `Button.tsx`) is DEFENSIVE. It is correct when the shape appears, but no real repo screened has it, because a `.tsx` library is almost always bundler-built. Unit tests plus mutation checks are the right level for that arm — do not burn hours hunting a repo to exercise it, and do not "fix" it by editing a third-party repo until the shape appears, which turns a real-repo check into a synthetic fixture wearing real clothes.

SCREENING LESSON: verify the shape on the ACTUAL CLONE, never from a raw.githubusercontent read of a branch path. `raw.githubusercontent.com/.../main/packages/react-table/tsconfig.json` advertised rootDir+outDir; the depth-1 clone of the same repo had neither. That cost an install, a build, and 1.7 GB.
