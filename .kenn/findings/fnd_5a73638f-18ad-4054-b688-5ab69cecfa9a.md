The atlas domains axis keeps a flat-Louvain community when it clears MIN_DOMAIN_SIZE AND EITHER (a) it spans >1 anchor (cross_anchor — the always-valid rule) OR (b) the repo is single-dominant: one anchor owns the majority of production nodes (top_prod*2 > total_prod), so a monolithic library still surfaces intra-package domains. Rule (b) is guarded — the >=2-spanned-packages filter is dropped ONLY when single_dominant, so a multi-package repo is never flooded with intra-package communities that merely shadow its packages. Members stay restricted to domain-eligible nodes (non-container, non-test, non-example, code + anchored). build_domains in atlas/producer.rs; determinism rides on louvain_flat. Supersedes the earlier cross_anchor-only rule.
