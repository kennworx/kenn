Real-repo validation of CSS/Sass cross-producer features (run via `kenn index` on bootstrap/bulma + a synthetic TS+CSS-Modules `webapp` fixture under tmp/corpora/, queried by sqlite over the run's code.db). Findings: (1) §11 code→stylesheet imports WORK end-to-end on real TS — `app.tsx` importing `./button.module.css` (default) AND `./theme.css` (side-effect) both produced module→module `imports` edges. (2) §9 check_css validates: bootstrap 12 orphan stylesheets (incl. alternate entry bundles bootstrap-grid/reboot/utilities.scss — the documented usage-off caveat where entries with no inbound imports look orphaned), orphan_class correctly skipped (0 uses_css_class → usage_mining_on=false gate fires). (3) §8 extends_rule has ~NIL real-world yield: bootstrap/bulma use `@extend %placeholder` (deferred — no placeholder kind) almost exclusively; the only form we emit (`@extend .class` between bare-class rules) barely appears, and bootstrap's `.class` @extends sit in compound/&-nested enclosing rules (e.g. `.btn-group-sm > .btn { @extend .btn-sm }`) which correctly yield no edge. The `composes` (CSS Modules) form is where extends_rule actually fires, but only in app code, not libraries. (4) BUG FOUND + FIXED — `uses_css_class` (§7.2 token scan + §7.3 module-member binding) produced ZERO edges on real TS because kenn-ts emits DECLARATION-LINE-ONLY def ranges (every TS function has start_line==end_line; verified across the main repo), so `find_at_location` never resolves a body-level usage, and the v1 code skipped when no enclosing symbol resolved. Fix (`css/ingest.rs`): `enclosing_or` helper falls back to the file's MODULE node (via `module_of_file`, a queryable symbol — preferred over the raw file node because file/symbol short-ids share space and a file-node src wouldn't hydrate via list_inbound's symbols join), else the file node. This is what spec §7.2 already prescribed ("otherwise the code file node"); v1 had not implemented it. After the fix, webapp `s.btnPrimary`/`s.btnSecondary` resolve Exact to `.btn-primary`/`.btn-secondary` attributed to the app.tsx module. LESSON: the e2e tests passed despite the bug because they SEEDED body-covering def ranges (lines 1-3), masking kenn-ts's real decl-line-only shape; added `usage_falls_back_to_module_when_no_enclosing_symbol` which seeds a decl-line-only range to lock the fix. Corrects the "v1 attaches to SYMBOLS only" claim in prior findings.
