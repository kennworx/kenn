The code->table pass has an ORM ceiling, and it is a property of the corpus rather than a defect to fix in the SQL parser. Measured on a 4442-file C# codebase: 388 files reach the database through Entity Framework or Dapper, where table access is expressed as LINQ over entity types and NO SQL TEXT EXISTS to parse; only 24 files contain a SQL-ish string literal at all, and 13 of those are interpolated ($"SELECT ..."), i.e. runtime-assembled fragments the pass deliberately drops. The pass found 19 sites there — good recall on what is findable. So when a code->table run reports few code-language sites next to thousands of XML/SQL ones, do NOT treat it as a producer bug: measure the ORM share first. Raising it requires an ORM-model pass (entity type -> table mapping), which is a different producer, not a better parser.
