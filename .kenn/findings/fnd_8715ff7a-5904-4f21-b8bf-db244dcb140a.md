Zero-range def rows are NOT remaining debt to remove from the producer — do not "finish" the old deferred bug by deleting the placeholder in push_def_records (transform/document/walk.rs). Measured on a self-index AFTER the finalize DELETE: 143 rows remain, ALL first-party (external=0), and ALL are their symbol ONLY def. Their kinds say why they have no SCIP Definition occurrence and never will: associated types in trait impls (`impl From<X> for Y { type Error = … }`, `Deref::Target`) which rust-analyzer describes without an occurrence, and TypeScript file-level `module` symbols, which have no token range because a file is not a token. The placeholder is LOAD-BEARING: `defs` is the symbol-to-file link for aggregation (`primary_def_file` in aggregate.rs, built from scan_def_files_for_aggregation), so dropping it orphans those 143 symbols from their file and therefore from package and atlas attribution. A test pins this (`transform_document_emits_placeholder_def_when_no_definition_occurrence`) and it caught the removal. What WAS the bug is fixed: a placeholder shadowing a real def is deleted at finalize (measured 0 remaining), and every read path skips start_line==0, so no caller gets a wrong location. The honest residue is that these symbols have no source location — which is true, not a defect; fabricating one would be worse.
