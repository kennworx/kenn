The markdown (content) walk spans the WHOLE tree, so it INHERITS its excludes and hardcodes NONE. `markdown_with_inherited_excludes(config, ws_root)` in workflow.rs ALWAYS (never gated on "is the markdown excludes list default") builds the effective exclude set = the workspace-internal excludes UNION every language's build/vendor `.excludes`:

- workspace-internal: the git dir resolved via `kenn_store::git::git_dir` (NEVER a literal `.git` — it follows GIT_DIR / worktree gitdir), kenn's committed store dir from `Layout::committed_root` (NEVER a literal `.kenn` — derived from the store config), and `[workspace].excludes`.
- per-language: `config.language.{rust,ts,csharp,python,go,swift}.excludes` — the SINGLE source of truth for target/node_modules/.build/obj/vendor. Unioned for ALL six languages even when a language is disabled, because each `LanguageConfig.excludes` defaults to its own dir globs (so e.g. `.build/**` from SwiftConfig applies even with Swift off).

`[language.markdown].excludes` only ADDS repo-specific dirs (tmp/, build/, .claude/, …). To index UNDER an otherwise-excluded dir (e.g. generated docs committed in a build dir), the user adds a glob to `[language.markdown].includes` (new field) — includes WIN over excludes at discovery (markdown/discover.rs descends into an excluded dir only when includes are present, then filters per file).

NEVER hardcode a global exclude (node_modules / target / .kenn / .git) in a content or language config's defaults — source it from the owning layer (a language's own excludes, or the workspace/layout). This runs through the shared `configure_runner`, so both the CLI (`cmd_index`) and MCP (`workflow`) index paths get it. Corollary correction to prior guidance: `[workspace].excludes` is NOT code-only anymore — the markdown walk inherits it. Do NOT reintroduce a `MarkdownConfig::DEFAULT_EXCLUDES` list or gate inheritance on it.
