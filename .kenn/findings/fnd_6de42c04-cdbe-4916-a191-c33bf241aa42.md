kenn's docker-runtime (runtime = "docker") must cover EVERY indexer language, never a convenient subset. Each code driver needs either a published image under docker/<name> WITH a matrix entry in .github/workflows/images.yml, OR a documented blocker in the change's tasks.md saying why not — a language silently left imageless degrades to the text fallback with no symbol graph and no error.

Two image shapes: external-tool images (rust-analyzer/scip-go/scip-python) just install an upstream indexer on PATH; sidecar images (kenn-ts/kenn-dotnet/kenn-swift) bake kenn's OWN binary and must keep the language's SDK in the FINAL image because the sidecar drives the target's build system at index time — kenn-dotnet needs the .NET SDK (MSBuildLocator spawns dotnet --info + dotnet restore), kenn-swift needs the Swift toolchain (swift build). A minimal runtime base fails at index time. kenn-ts is the exception: bun-compiled + self-contained, only needs git.

Known blocker: kenn-swift cannot be containerized until Foundation.Process is replaced with a posix_spawn runner — it deadlocks in swift:6.x Linux containers both at swift-index-store manifest eval (building the image) and at runtime swift build.
