rust-analyzer emits NO SCIP SymbolInformation.relationships — Rust's implements edges come from the MONIKER. Measured on real repos: scip-go (544 edges) and scip-python (129) DO populate relationships, so the is_implementation arm in transform/document/walk.rs covers them; rust-analyzer populates none, which made Rust the only indexed language with zero implements edges and 'kenn list implementers <trait>' permanently empty. The relationship survives STRUCTURALLY in the descriptor: 'impl#[Type][Trait]member' for a trait impl, 'impl#[Type]member' for an inherent one. kenn_model::id::trait_impl_of requires EXACTLY two type params — accepting one invents an implements edge for every inherent impl, and inherent impls outnumber trait impls in real Rust. Detect structurally; never by a name heuristic over the pub_id. RESOLUTION IS THE HARD PART: rust-analyzer writes both names BARE ('[Default]', never its defining crate), so they are resolved against the types referenced in the SAME document — 'impl Default for Foo' necessarily references the real Default there, which is how std traits (64 of this workspace's 117 edges) land edges despite existing in no workspace crate; a workspace-trait table alone drops two thirds. TWO guards are load-bearing and must not be dropped as redundant: a name matching more than one referenced symbol is SKIPPED, never guessed (two same-named traits referenced in one file is the ambiguity document-scoping cannot resolve); and a name resolving to a symbol the document DEFINES as struct/class/enum/union is rejected, or a macro- or derive-expanded impl whose trait produced no occurrence would attach to a same-named struct and report a type that implements nothing.
