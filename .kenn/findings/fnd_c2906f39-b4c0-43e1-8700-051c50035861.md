scip-python CANNOT be bundled with 'bun build --compile' — do not retry the spike. It is a webpack build with split chunks: dist/scip-python.js loads dist/vendor.js and dist/pyright-internal.js through the webpack runtime's COMPUTED require, which no bundler resolves statically (a naive compile bundles 2 modules and dies with "Cannot find module './vendor.js'"). Requiring the chunks explicitly DOES embed them (bundle goes to 4 modules), but a shim over Module._load is inert: bun's compiled binary resolves internal requires through its own resolver, not node:module. Making it work means patching the published dist/ or re-running webpack against scip-python's source — i.e. maintaining a build of a third-party tool.

The economics never justified it anyway: bun's runtime floor is 63MB native / 89MB musl against node's 126MB binary, so compiling swaps one JS runtime for another and saves ~37MB. dist/typeshed-fallback is 18MB of .pyi DATA read by path at runtime (via global.__rootDirectory) and ships loose either way — no bundler embeds it.

The right shape instead: node is a TOOLCHAIN, provisioned into the shared cache like any other, so the python image carries only scip-python's 31MB dist/. scip-python also shells out to 'pip list' and reads the project version from git at INDEX time, so python3+pip must be reachable from the toolchain cache, not merely at build time.
