md→code FILE links use a dedicated `EdgeKind::LinksToFile` (db_name `links_to_file`, code 13), a sibling of `contains`. This RESOLVES the earlier file/symbol ShortId-collision limitation: the graph disambiguates a file-vs-symbol edge target *by edge kind*, so file-target links hydrate from the files table (sound forward nav AND code-file→md backlink), with NO exclusion needed. `CodeTarget` carries `is_file` (set in `resolve_code_link`'s file branch); `resolve_markdown_code` emits `EdgeProperties::LinksToFile { grade }` for file targets and `LinksTo`/`Embeds` for symbol/md targets. `check_links` (MCP, the FIRST edge-payload reader) reads the `link_grade` column via `DbReader::scan_link_diagnostics`: it scans `links_to`/`embeds`/`links_to_file` edges with md source and grade != exact, hydrating each target by edge kind (`links_to_file` → files.path; others → symbols.pub_id; a dangling stub's `md:!unresolved/<written>` pub_id is decoded to the written target). Adding a new file-targeting EdgeKind requires: the EdgeKind+EdgeProperties variants (kenn-model edge.rs), edge_kind_code + ALL_EDGE_KINDS (kenn-store codes.rs), the writer flatten arm (writer/core.rs), and a files-table read path for that kind.
