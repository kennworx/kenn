kenn-mcp observability is unified on the tracing + metrics stack, not ad-hoc log lines. Wrap each tool call in ONE tracing span carrying the tool name, whose open→close is the call's duration, at the single dispatch boundary — a custom `ServerHandler::call_tool` (the rmcp `#[tool_handler]` macro skips generating its own `call_tool` when you define one in the impl block, so you delegate to `Self::tool_router().call(...)` under `.instrument(span)`). Emit metrics through a facade at the same point (the `metrics` crate: a call counter + a duration histogram keyed by tool) so a backend exporter (OTLP/Prometheus) is a config flip, not a refactor — no exporter is wired yet, so the macros are a no-op. All observability output (spans/logs/metrics) goes to STDERR or an exporter — NEVER stdout, which the MCP stdio transport reserves for JSON-RPC; the subscriber is stderr-bound with FmtSpan::CLOSE so span durations are emitted.
