cmd_index::run_async (CLI 'kenn index') and workflow::index_workspace (workflow/MCP) are PARALLEL orchestrations of one index run. Every shared step now goes through a single-source helper in kenn-indexer: build_workspace + configure_runner (workflow.rs); the report helpers aggregate_status / collect_failed_projects / render_overview_md (report.rs); and the snapshot writer SnapshotMeta / SnapshotCounts / aggregate_counts / build_snapshot_meta / persist_run_artifacts (snapshot.rs). BOTH paths call the same writer, so meta.json / report.json / overview.md are identical (the CLI additionally computes regression_warnings; the MCP path passes none). SnapshotMeta lives in kenn-indexer::snapshot and is READ back by kenn-cli's cmd_status ('kenn status'). Do NOT reintroduce a per-entry-path copy of ANY of these — add a language, producer, exclude, or meta field ONCE in the shared helper. This drift has bitten repeatedly (markdown, dotnet test_globs, Swift excludes, hardcoded meta status='success'). Regression tests: crates/kenn-indexer/tests/{markdown_producer_parity,build_workspace_parity,meta_status_parity}.rs.
