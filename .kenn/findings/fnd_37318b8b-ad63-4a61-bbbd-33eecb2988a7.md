MCP `parse_kind` / `parse_language` (crates/kenn-mcp/src/tools/support.rs) MUST delegate to the model's `Kind::from_db_name` / `Language::from_db_name` rather than hand-rolling the variant→enum match. The hand-rolled copies silently omitted the markdown `document`/`section` kinds and the `markdown` language, so md nodes surfaced through nav/search (`find_symbol`, `find_at_location`, etc. via `symbol_row_to_ref`) with the wrong kind/language (fell back to `variable`/`rust`). `symbol_row_to_ref` uses `parse_kind(..).unwrap_or(Variable)` and `parse_language(..).unwrap_or(Rust)`, so a missing arm is silent, not an error. Rule: any DB-string→model-enum conversion in kenn-mcp routes through the single canonical `from_db_name` mapping, so a newly added Language/Kind variant is never dropped at the MCP boundary.
