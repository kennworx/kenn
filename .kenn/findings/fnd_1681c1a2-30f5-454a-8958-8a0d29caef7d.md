Docker Swift indexing missing `calls` (task #45) — ROOT CAUSE: on the Linux swift:6.3 toolchain, `swift build --experimental-prepare-for-indexing` produces an index store WITHOUT call relations (only implements/imports/overrides), while a PLAIN `swift build` produces a complete store WITH calls (verified: 5 calls edges on the SampleApp fixture in-container). macOS prepare-for-indexing DOES include calls — a platform difference (calls appear tied to codegen, which prepare-for-indexing skips; Linux records them there, macOS earlier). The reader is fine (it emits calls from the plain-build store). runSwiftBuild in Provisioning.swift tries prepare-for-indexing FIRST and only falls back to plain build on failure, so on Linux it never gets calls. FIX OPTIONS: (a) flip to plain-build-PRIMARY + prepare-for-indexing FALLBACK — compiling packages get calls on every platform; broken packages fall back to prepare (symbols only, error-tolerance preserved). Cost: plain build does full codegen (slower than prepare) — mitigated by the .build cache volume (#42); requires updating testPrepareRejectedFallsBackToPlainBuild (the order assertion inverts). (b) keep prepare-first, accept no-calls in docker (document limitation).
