Verifying the kenn-swift Linux build in Docker on a macOS host: swift:6.0/6.1 images hang forever at swift-index-store's manifest evaluation, because Foundation Process + pipe + waitUntilExit deadlocks in those containers (a 5-line repro hangs; not sandbox, not bind mounts, not arch emulation, not --init, not seccomp) and that dependency's Package.swift spawns 'which swiftc' on Linux. Working recipe: tar-pipe the package sources into the container (never bind-mount for this), git clone swift-index-store, overwrite its Package.swift with a copy whose #else Process block is replaced by ProcessInfo environment lookup of KENN_TOOLCHAIN_LIB (default /usr/lib), sed kenn-swift's dependency to .package(path: "../swift-index-store"), export KENN_TOOLCHAIN_LIB="$(dirname "$(dirname "$(readlink -f "$(command -v swiftc)")")")/lib", then swift build.
