C# indexing MUST restore. [language.csharp] restore (default TRUE) drives KennDotnet.skip_restore, wired in workflow::configure_runner — the single KennDotnet construction site, so both the CLI and MCP index paths get it. Without a restore, MSBuild binds no NuGet assembly: every package type degrades to a BARE syntactic name while the run still exits 0 with symbols and NO diagnostic — a SILENT fidelity loss. Proven by pub_id A/B on one fixture: unrestored 'cs:Probe#Dump+JsonSerializerSettings' vs restored 'cs:Probe#Dump+Newtonsoft.Json.JsonSerializerSettings'. It only looked harmless because a dev machine's obj/ is already restored by its own builds; runtime="docker" and clean CI checkouts have none. The AccessViolationException that once justified --skip-restore (CopyToAsync draining dotnet restore's pipes corrupts an ArrayPool buffer on macOS) is FIXED by SolutionLoader's blocking drains and is guarded by 'just index-stability' (0 aborts / 8 runs). A failed restore is NON-fatal: it logs a warning and indexing continues, so enabling it is safe offline. Do NOT re-hardcode skip_restore=true.
