kenn-dotnet discovers .sln only — a repo whose solution is the newer XML .slnx format indexes NOTHING. Found on JamesNK/Newtonsoft.Json, which ships Src/Newtonsoft.Json.slnx and no .sln; it was previously mischaracterized in this repo's notes as a 'csproj-only repo', which sent the diagnosis in the wrong direction. MSBuild 17.13+ understands .slnx, so this is a discovery-glob gap in the sidecar, not an MSBuild limitation.

Consequence matches the baked-toolchain failure mode and is just as quiet: no solution found means zero files at exit 0, not an error. When picking a C# verification target, confirm it has a classic .sln (serilog/serilog does — 216 files, 3444 symbols) or the run proves nothing about the image.
