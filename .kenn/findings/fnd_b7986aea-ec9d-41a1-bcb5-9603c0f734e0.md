The pub_id is handed to the shell as a kenn get <pub_id> argument (also find/relations/MCP), so it MUST be a single unquoted POSIX-shell-safe token. Today id formation emits shell-hostile chars in every language (backticks, (), <>, spaces, [], etc.). The fix — a safe-delimiter grammar (+ call, ~ generic, , siblings, = fn-return), reserved _word_ type-constructors (_array_/_tuple_/_optional_/...), external-leaf rendering, and a _x<NN>_ totality floor, applied at the shared intern_with_pub_id funnel (transform/registry.rs) — is fully specified in openspec/changes/shell-safe-symbol-ids (not yet implemented). When you touch id formation, keep ids shell-safe per that grammar. Note: edge.rs reads the SCIP wire symbol, NOT the pub_id, so it needs no change.
