A TypeScript declaration extension is NOT invertible one-to-one — treat the outDir remap as a candidate LIST, and pick the candidate that was actually indexed. `OutDirMap.toSource` matched only `.d.ts` and mapped it only to `.ts`, which lost two whole classes of cross-package edge:

- `.d.mts` / `.d.cts` are what a dual ESM+CJS build emits (tsup, unbuild, modern tsc). Unmapped, so every cross-package reference into such a package kept keying to BUILD OUTPUT — the exact defect OutDirMap exists to remove, spelled differently.
- `Button.tsx` compiles to `Button.d.ts`. Mapping to `.ts` alone produced a path that does not exist, so the reference silently lost its edge. Every `.tsx`-authored component exported from a workspace package was affected.

`isExternalPath` had the same `.d.ts`-only test, and that one is WORSE than a lost edge: a workspace-internal `dist/index.d.mts` is under the root and not in node_modules, so it was classified INTERNAL and the build output became a first-party symbol competing with its own source. Use the shared `isDeclarationFile` for every such test.

Resolve ambiguity with `ids.hasFull(key)`, never the filesystem and never a guess: build a candidate key per candidate path and keep the first already emitted as a full symbol. That is the same truth source the callers already use, needs no new plumbing, and keeps the "degrade to no-edge, never to a wrong edge" property — with no candidate indexed, keep the FIRST so behaviour matches the old single-candidate case rather than newly emitting an external stub for build output.

COVERAGE GAP, stated because it is easy to overclaim here: this is unit-tested with mutation checks on both halves, but NOT verified end-to-end. The remap only fires on a monorepo whose packages are BUILT (a `types` field resolving into `dist/`), and a fresh clone of the roster TS repo has no `dist/` and no `.tsx`. Exercising it for real needs a built TS monorepo that uses `.tsx` or a dual build.
