kenn-store pool-backed reader dispatch style (crates/kenn-store/src/db/sqlite/reader/). The query logic is sync methods on `SqliteConnRef<'a> { conn: &'a Connection }`; inside those methods use the `self.conn` FIELD directly (e.g. `self.conn.prepare_cached(...)`, `fetch_symbols_by_ids(self.conn, ...)`) — there is no `conn()`/`graph()`/`knowledge()` accessor and no pointless `let g = self.conn;` single-use alias (a local is only justified when used several times). The async surface lives in reader/reader.rs (the `impl Reader for SqliteReader` + the inherent extras find_similar_symbols/code_node_resolver/stats). Every dispatch method is one line through the `SqliteReader::with_conn` helper, which hides the `pool.conn_and_then(move |conn| f(SqliteConnRef { conn }))` boilerplate — so each method body is just `self.with_conn(move |c| c.some_core(args)).await`, with borrowed args cloned into the 'static closure. When adding a reader method: write the sync core on SqliteConnRef (using self.conn), then a one-line with_conn dispatch on SqliteReader, then a thin delegation on DbReader (DbConn is a type alias of DbReader).
