Splitting a large Rust module past the `just large-files` 30k budget: convert `X.rs` to a directory module `X/` following the repo convention — `X/mod.rs` holds ONLY `mod`/`pub use` declarations (no code), the code moves to `X/core.rs` (or concern-named files for a genuine multi-part split like tools/query → lookup/nav/usages or server → core/handler/env/errors). Four hazards when code moves one directory deeper, all compiler-caught but easy to miss: (1) `super::<sibling>` paths must become `super::super::<sibling>` — but ONLY at the file top level; a `super::` inside an inner `mod {}` refers to the file itself and must NOT be bumped. (2) `pub(super)` items that OTHER sibling modules rely on must become `pub(in super::super)` to keep the same visibility ceiling. (3) `include_str!("../asset")` gains a directory level → `../../asset`. (4) When a section boundary falls between an item and its leading `#[derive]`/doc-comment/`const`, cutting at the `pub fn`/`pub struct` line splits the attributes off — cut at the blank line before the doc/attribute. For unit tests that reach the code's PRIVATE items, keep tests a child of the code module: `X/core.rs` ends with `#[cfg(test)] mod tests;` and the body lives in `X/core/tests.rs`, so `use super::*` still sees privates with zero visibility widening. Move test bodies verbatim (no dedent) and let `cargo fmt --all` re-indent — a blind `sed` dedent corrupts multi-line raw-string fixtures. After splitting, `cargo fix --lib --tests` strips the now-unused preamble imports each concern file inherited. Splitting an rmcp `#[tool_handler] ServerHandler` away from its `#[tool_router]` impl needs `#[tool_router(vis = "pub(super)")]` (so the generated `tool_router()` fn stays reachable from the handler module) plus `pub(super)` on the `tool_router`/`state` struct fields. Verify no test was dropped by comparing `#[test]` counts against git HEAD per file.
