CSS usage mining is implemented (Phase 2 v1) across `css/usage.rs` (pure) + `css/ingest.rs` (store-backed barrier) + `pipeline/api.rs` (wiring). Flow: (1) `ingest_css_phase1` returns `CssPending { usage_files }` discovered from `usage_sources` globs (any file type; empty config ⇒ empty ⇒ mining off + a one-time hint). (2) post-code barrier `resolve_css_usage_unit` (sibling to `resolve_markdown_code_unit`, runtime-free thread, gated on `has_code`) opens `reader_from_writer` and runs `resolve_css_usage`. (3) `usage::extract_candidates` pulls class-shaped tokens from STRING LITERALS only (not bare identifiers), tagging `ClassAttr` (within ~64 bytes of class=/className=/clsx/cn/cx/classList) vs `OtherString`, with byte offset. (4) `resolve_usages` intersects with a `ClassRegistry` (store impl filters `symbols_by_short_name` by `#class:` pub-id fragment) → grade Exact (attr) / Fuzzy (other) / Ambiguous (>1 def); misses → undefined set (no nodes). (5) each hit's offset → 1-based line → `reader.find_at_location(file_id, line)` (Reader trait) smallest enclosing symbol → `uses_css_class` edge symbol→class. v1 attaches to SYMBOLS only: if no enclosing symbol or the file isn't in the code graph (`fetch_file_short_id` None — e.g. HTML), the usage is skipped. DEFERRED: 7.3 CSS-Modules binding (`import s from './x.module.css'; s.foo`, JS/TS, camel↔kebab fold); HTML/file-level sourcing; the `check_css` report consumer of the undefined set (Phase 3 §9).
