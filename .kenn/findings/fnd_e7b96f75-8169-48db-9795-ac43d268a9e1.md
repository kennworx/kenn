Atlas package `description` seeding (build_concepts, atlas tasks 3.4/8.4) picks the root-module file from ALL files under the package root (the `files` map filtered by the resource prefix), NOT just symbol-def files. A Rust `lib.rs` defines only the crate module (a container kind, excluded from the atlas anchor/central set) plus `mod`/`pub use` re-exports, so it carries no first-class symbol and never appears in the package's member/def files — yet it holds the crate's module doc. `pick_root_file` is language-keyed (lib.rs/main.rs, index.ts, __init__.py, doc.go), ties broken shallowest-then-lexicographic; the description is that file's `file_docs` row, verbatim, None when absent (never synthesized). Docs are read via DbWriter::scan_file_docs on the writer's own connection, like the analysis scans.
