A markdown wikilink/embed target that does not resolve to a note and has a non-markdown MIME type is modeled as `Kind::Attachment`, NOT a `document`/`markdown` node (the prior bug: `![[diagram.png]]` showed as "document · markdown"). `external_stub` in kenn-indexer/src/markdown/ingest.rs classifies via `attachment_mime` (mime_guess::from_path on the target; Some and essence != "text/markdown" → Attachment, else Document), so png/pdf/css/svg become attachments while extension-less or `.md` targets stay dangling notes. `Kind::Attachment` (kenn-model/src/kind.rs) is a roll-up leaf in aggregate.rs so embeds land on it. The kenn-analyze renderer derives the displayed type from the filename's MIME (e.g. image/png) via mime_guess and colors attachments by MIME top-level type; BOTH the hover panel and the selection panel must show the MIME for attachments, not the (markdown) language.
