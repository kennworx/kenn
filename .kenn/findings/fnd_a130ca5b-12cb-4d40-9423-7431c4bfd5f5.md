The /kenn:squeeze ritual can break the NEXT `just test`. `kenn findings add` (and other CLI commands that touch embeddings) runs the embedder selector, which auto-spawns a local `kenn server` daemon with a 600-second lifetime; on macOS that daemon holds the Metal device, so a `just test` started inside that window fails the 7 vector-dependent `kenn-store/tests/hybrid_search.rs` tests with "left: 0, right: 5" — zero embeddings produced. This is NOT the failure mode CLAUDE.md §11 describes. §11 says to check the invocation first, and here the invocation is already correct: `just test` sets KENN_EMBED_IN_PROCESS=1, which prevents the test binaries from spawning a daemon but cannot evict one that another process already started. Symptoms that identify it: the suite passes when run alone (`KENN_EMBED_IN_PROCESS=1 cargo test -p kenn-store --test hybrid_search`) with ggml_metal_device_init succeeding, and `ps aux | rg "[k]enn server"` may already show nothing because the 600s window elapsed while you were diagnosing. Order the ritual accordingly: run the full suite BEFORE the squeeze, or wait out the window after it.
