kenn-swift spawns ALL subprocesses (swift build, xcodebuild) through ProcessRunner (indexers/kenn-swift/Sources/kenn-swift/ProcessRunner.swift) — NEVER Foundation.Process directly. On POSIX ProcessRunner uses posix_spawn + waitpid; Foundation.Process run()+pipe+waitUntilExit DEADLOCKS in swift:6.x Linux containers (a 5-line repro hangs; not sandbox, bind mounts, arch emulation, --init, or seccomp). Windows keeps Foundation.Process (no such bug there, and no posix_spawn). Two gotchas when editing ProcessRunner: (1) drain the child stdout pipe to EOF BEFORE waitpid, or an output larger than the pipe buffer deadlocks; (2) posix_spawn_file_actions_t is an OPTIONAL heap pointer on Darwin (var actions: posix_spawn_file_actions_t?) but a STRUCT on Glibc (= posix_spawn_file_actions_t()) — declare it per-platform, then pass &actions to init/adddup2/destroy/posix_spawn uniformly. REMAINING container blocker (separate, build-time): swift-index-store Package.swift spawns Process during MANIFEST EVAL, needing the vendored env-var manifest patch (see fnd_89957a89).
