Every MCP tool error message must name a concrete recovery action the agent can take next — a specific tool to call or a CLI command to run — not merely describe the failure. A raw failure string with no next step makes agents invent a cause (e.g. "looks like a path/permission issue") and abandon kenn entirely instead of retrying. Examples in error.rs: INDEX_UNAVAILABLE on a Failed index tells the agent the watcher retries on the next change, or to call the `reindex` tool now, or run `kenn index` to rebuild; an empty snapshot with no kenn.toml points at `kenn init`; the Indexing variant says to poll get_index_status and retry once state==ready. When adding or editing an McpError, include the recovery path.
