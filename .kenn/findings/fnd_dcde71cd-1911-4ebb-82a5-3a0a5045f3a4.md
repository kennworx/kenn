Docker indexer-runtime cache volumes (crates/kenn-indexer/src/docker.rs). Two kinds, both NAMED volumes (never a host bind mount — bind-mounting a hot cache crosses the host<->VM boundary on macOS/Windows, a severe I/O penalty), created root-owned so kenn must docker-volume-create + chown to the invoking uid before a --user container writes them.

1. DEPENDENCY-SOURCE cache (CARGO_HOME/GOMODCACHE/NUGET_PACKAGES/pip/npm). DEFAULT is PER-REPO: kenn-deps-<hash> bound to the repository MAIN worktree (via kenn_store::git::main_worktree) and shared by all its worktrees, so deps download once per repo and the volume is reclaimable when the repo is deleted. Setting [docker].cache_volume opts into ONE shared cross-repo volume instead (bound to nothing). SUPERSEDES prior guidance that the default was global-shared cross-repo; it is now per-repo.

2. BUILD-ARTIFACT cache (cargo target/, GOCACHE) — NEVER shared across repos (cargo locks target/ so a shared cache deadlocks parallel runs); ephemeral by default, or a PER-WORKTREE kenn-build-<hash> volume under [docker].persist_build_cache.

Naming + labels are the single source of truth in docker.rs: build_volume_name(worktree) and deps_volume_name(main_worktree) both hash the bound dir via one dir_hash, so the creator (indexer) and remover (kenn docker-cache) always agree. Every kenn volume carries TWO labels: kenn.managed=true (LABEL_MANAGED, the enumeration key — kenn docker-cache finds volumes by --filter label=kenn.managed, so the shared volume is visible too) and, on a DIR-BOUND volume only, kenn.workspace=<abs-dir> (LABEL_WORKSPACE, the orphan-binding key — --orphans reaps a volume iff its labelled dir no longer exists; the shared volume lacks it and is never an orphan). Volume wiring lives in the SHARED configure_runner (workflow.rs) so both kenn index (CLI) and MCP reindex get it (parity, see fnd_4c015b98).
