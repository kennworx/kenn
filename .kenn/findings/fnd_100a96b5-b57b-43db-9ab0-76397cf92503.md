kenn-analyze graph.html viewer (cosmos.gl @cosmos.gl/graph 2.6.4) gotchas, hard-won: (1) cosmos calls preventDefault on `pointerdown`, which suppresses the compatibility mousedown/mouseup/click events — a mouse-`click` handler silently never fires (but `mousemove` still works). Drive hover from `mousemove` and CLICK from POINTER events (pointerdown/pointerup) registered in the CAPTURE phase (cosmos stops propagation in bubble for its pan), telling click from pan by pointer travel. (2) `spaceToScreenRadius(size)` returns the point's on-screen DIAMETER (our `sizes` are diameters) and applies cosmos' point-size scale `min(5, max(1, k*0.01))`, which is NOT the camera position scale `k` — convert POSITIONS with `spaceToScreenPosition` and SIZES with `spaceToScreenRadius`; mixing them makes the hit-area/ring drift from the rendered point on zoom. (3) The ring marking the hovered/info point is a fixed-thickness DOM overlay (#focus-ring) re-sized and re-positioned every frame to the point's rendered diameter — cosmos' built-in renderHoveredPointRing / focusedPointIndex ring scales with point size and zoom, which we don't want. (4) Hover/click use a custom generous nearest-point hit-test (per-point radius = rendered radius + pad, with a screen-px floor) so tiny dots are reachable. Node visibility toggles (code / markdown / attachments) filter by language plus Kind::Attachment.
