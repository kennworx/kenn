Adding a new graph edge kind threads through MORE layers than the wire enum — miss one and you get a build error or a silently dropped edge. The full checklist (learned adding `extends_type`):

1. `indexers/kenn-dotnet/src/Wire/EdgeKind.cs` — enum variant + `ToWireString` + `TryParseWireString` (for any JSONL producer).
2. `indexers/frames.ts` — the `EdgeKind` union (keep the string spelling identical across C#/TS/Rust).
3. `crates/kenn-model/src/edge.rs` — `EdgeKind` variant, `db_name` arm, `EdgeProperties` variant (unit variant if the edge carries no payload, like `Implements`/`Overrides`), `EdgeProperties::kind` arm, and the `edge_properties_kind_covers_every_variant` test arm.
4. `crates/kenn-store/src/db/codes.rs` — `edge_kind_code` AND `ALL_EDGE_KINDS`. APPEND the next integer code; never insert/renumber — existing on-disk indexes key edges by these codes and renumbering corrupts them.
5. `crates/kenn-indexer/src/edge.rs` — the SCIP-occurrence classifier `edge_properties`. A producer-emitted edge (from a JSONL sidecar, or the markdown/css producers) never derives from a SCIP occurrence, so it goes in the `unreachable!` group with `LinksTo`/`UsesCssClass`/`ExtendsRule`, NOT a real arm.
6. `crates/kenn-indexer/src/transform_jsonl/records.rs` — the `edge_properties(kind, field_op)` string decoder arm (this is the JSONL consumer's path, separate from #5).

The MCP `find_usages`/`list_usages` `edge_kinds` param needs no change — it deserializes `Vec<EdgeKind>` straight from serde/schemars, so the new variant is accepted automatically (and stays out of the default reference set unless you add it).
