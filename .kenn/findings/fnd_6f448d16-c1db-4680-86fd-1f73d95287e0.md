kenn docker-runtime (runtime = docker) must cover EVERY indexer language, never a convenient subset. Each code driver needs either a published image under docker/<name> WITH a matrix entry in .github/workflows/images.yml, OR a documented blocker in the change tasks.md saying why not — a language silently left imageless degrades to the text fallback with no symbol graph and no error.

Two image shapes: external-tool images (rust-analyzer/scip-go/scip-python) install an upstream indexer on PATH; sidecar images (kenn-ts/kenn-dotnet/kenn-swift) bake the kenn binary and must keep the language SDK in the FINAL image because the sidecar drives the target build system at index time — kenn-dotnet needs the .NET SDK (MSBuildLocator spawns dotnet --info + dotnet restore), kenn-swift needs the Swift toolchain (swift build). A minimal runtime base fails at index time. kenn-ts is the exception: bun-compiled + self-contained, only needs git.

RESOLVED (was a blocker): kenn-swift IS now containerized. Foundation.Process (which deadlocks in swift:6.x Linux containers) was replaced by a posix_spawn ProcessRunner for the runtime swift build, and docker/kenn-swift/Dockerfile patches the swift-index-store Package.swift to read KENN_TOOLCHAIN_LIB from the env instead of spawning Process during manifest eval. All six indexers now have images and images.yml matrix entries; the kenn-swift image indexed Alamofire on Linux (3148 symbols, no hang).
