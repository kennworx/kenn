Atlas concept ids/filenames (okf.rs) use ONE separator everywhere: `_`. Runs collapse to a SINGLE `_` (collapse_underscores), never a doubled `__`, and ends are trimmed.

- packages (`concept_id`): `packages/<lang>_<anchor>` — path separators flatten to `_`, so a scoped `@atlas/strings` reads `packages/typescript_@atlas_strings`. The language prefix keeps a Rust `geo` and a C# `Geo` from colliding as filenames on a case-insensitive FS (mac/Windows).
- domains + contracts (`concept_slug`): alphanumerics kept, EVERY other char mapped to `_`, runs collapsed, ends trimmed, `fallback` when nothing survives.

The domain/contract half previously kept the name`s own `_` and mapped runs of other chars to `-`. Swift is what exposed it: an argument-labelled name is mostly punctuation, so `replacing(_:with:)` became `replacing-_-with` — three separator characters for one word boundary, none of them typed by anyone. Under the unified rule it reads `replacing_with`, and `AssertEqualStrings(actual:expected:file:line:sourceLocation:)` reads as its labels.

TWO INVARIANTS THIS BUYS. (1) A slug can never contain `-`, so the `-{n}` suffix `dedupe_domain_ids`/`dedupe_contract_ids` append to break collisions cannot be confused with slug content, and a symbol name cannot forge one. (2) One flattening rule for every id kind, so there is no per-axis separator to remember.

Changing the slug changes FILENAMES and every intra-bundle link at once, so verify both: after a reindex, every `](/...md)` target in the bundle must resolve on disk. Checked across six languages (362 link targets, 0 dangling). dep/domain links to OTHER anchors must reproduce the target`s exact id, so build_concepts builds an anchor->language map up front (plurality_language) and threads it into build_domains; the component-label render splits the id on `_`.

The concept id is atlas-internal, NEVER a pub_id — pub_ids in the concept body keep their exact grammar and are not escaped here (fnd_171ca5a6).
