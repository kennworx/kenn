The query CLI's output layer has a strict division: kenn-cli/src/render.rs owns the FORMAT CHOICE and the envelope; kenn-cli/src/toon/ prints only the items table. TOON is used for exactly ONE shape — an object whose fields are scalars or a list of uniformly-typed, NON-NESTED objects (items[N]{cols}: + rows). Anything nested (overview, get symbol — a field that is a struct, or rows with a nested field) is NOT TOON: write_table returns Err and render falls back to pretty JSON. Because a nested payload is only discovered mid-write, render decides the shape BEFORE touching stdout by serializing once to io::sink(), then streams the real table; nothing is ever half-printed. A wrapper's own scalar fields (next cursor, targets, truncated) are NOT columns — write_table drops them (skip_scalar) and render prints them as trailing lines, omitting nulls so a non-paginated result stays a clean table.

Why kenn has its own TOON encoder instead of the toon crate: that crate hard-sorts object keys alphabetically (three keys.sort() calls, no opt-out), which buried the resolvable id column mid-row. Ours is a direct serde Serializer, so COLUMN ORDER IS STRUCT FIELD DECLARATION ORDER — set where the view struct is defined (serde visits fields in order; nothing in the stack sorts). Corollaries that are load-bearing, do not regress them: (1) never route a result through serde_json::Value — its map is a BTreeMap and re-alphabetizes the keys, which is the original bug; (2) no type-erased carrier (Box<dyn Serialize>) — emit is generic over the concrete type and each subcommand emits its own typed result; (3) pagination merging is typed via the Page trait (items_mut/take_next), so even --all keeps field order; (4) scalars format straight to the writer (write! / write_str_token / write_f64), never via an intermediate String. Byte-compatibility with the upstream crate's table is pinned by toon::tests::matches_upstream_toon; the field-order guarantee by struct_field_order_drives_columns.
