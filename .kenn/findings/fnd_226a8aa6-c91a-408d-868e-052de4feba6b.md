Indexer image bases: prefer ALPINE, and measure before switching. Measured on arm64 (image total, after -> before): kenn-typescript 571MB->175MB, kenn-python 705MB->395MB, kenn-go 1.51GB->878MB, kenn-csharp 1.8GB->1.16GB (mcr sdk:10.0-alpine), kenn-rust 1.22GB->958MB (apk cargo/rust/rust-src/rust-analyzer). Non-obvious facts behind those numbers: (1) debian's git hard-depends on perl — 44MB git + ~55MB perl it never uses; alpine's git is a fraction. (2) FEDORA IS NOT SMALL: fedora:latest is 282MB and fedora-minimal 209MB on disk vs debian-slim 138MB — the 65-70MB you see on a registry page is the COMPRESSED size. Actual glibc ladder: distroless/base 43MB (no pkg mgr) < debian-slim 138MB < ubuntu 141MB < fedora-minimal 209MB < fedora 282MB. (3) musl's allocator is slower than glibc in general, BUT alpine's rust-analyzer links mimalloc2 and measured FASTER end-to-end (warm, alternating, 3 rounds: glibc 12-14s vs musl 8-9s indexing the same crate) — measure, don't assume. (4) bun --compile emits a glibc binary by default; pass --target=bun-linux-{x64,aarch64}-musl to run on alpine, and add libstdc++/libgcc. Cross-compiling from $BUILDPLATFORM also avoids QEMU on multi-arch builds. (5) YOU CANNOT SHRINK AN IMAGE BY rm-ing FILES THAT CAME FROM THE BASE — later-layer deletes only add a whiteout; the bytes still ship. Shrinking a base requires multi-stage COPY onto a smaller base. Always re-verify a base swap by INDEXING a real fixture, not by running --version.
