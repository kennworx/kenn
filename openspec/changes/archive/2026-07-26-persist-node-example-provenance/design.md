## Context

`is_domain_eligible(NodeFacts { id, language, kind, name, external, test, example })`
is shared by the atlas producer and the domains query. Six of the seven facts
come straight off the node row. The seventh does not:

| fact | producer | query |
|---|---|---|
| `name`, `kind`, `language`, `external`, `test` | node row | node row |
| anchored | `node_anchor` | `node_anchor` |
| **`example`** | **joins `primary_def_file` → `files` → `is_example_path`** | **`false`, hardcoded** |

`AggregateNodeRow` is `{ id, kind, name, language, external, test, anchor_id,
anchor_name }`. No path. The query has no way to answer the question, so it
answers a different one and the two surfaces disagree by one domain on this
repo.

`test` and `external` are already node-row facts. `example` is the same kind of
thing — provenance of the code, not policy about it — and is the only one of the
three that was left as a per-consumer derivation.

## Goals / Non-Goals

**Goals:**

- One evaluation of example-ness per index run, at a site that already holds the
  inputs, readable identically by every consumer.
- The domains query and the atlas render the same set, for the same snapshot,
  with no join and no fabricated argument.
- The example exclusion becomes specified behavior instead of an unspecified
  implementation detail of one function.

**Non-Goals:**

- Migrating existing snapshots. The store is regenerated by `kenn index`; a
  schema-version bump forces that and is the whole migration story.
- Making example-ness configurable. `EXAMPLE_SEGMENTS` stays a fixed convention;
  a knob is not requested and would need its own justification.
- Persisting the eligibility *verdict*. The verdict is policy and moves with the
  rule; the fact is stable. Storing the verdict would re-freeze the divergence
  one level up.
- Touching the language sidecars. Example-ness is a workspace path convention,
  not a producer's business — unlike `test`, which arrives on the wire.

## Decisions

### D1 — Persist the fact, not the verdict

`example: bool` joins `test` and `external` on `AggregateNodeRecord` /
`AggregateNodeRow` / the `aggregate_nodes` DDL.

The alternative — persisting `domain_eligible` — was rejected: eligibility is
policy that changes with the axis (the central-symbol list, the package axis and
the domain axis all want different subsets), so a stored verdict would be stale
the moment any of them moved. Path provenance is a fact about the source tree
and cannot go stale relative to policy.

### D2 — Evaluate in `build_aggregate_nodes`, not on the wire

`compute_and_persist` already materializes `files: HashMap<ShortId, String>` and
`primary_def_file: HashMap<ShortId, ShortId>` to call `resolve_anchors`. Passing
both to `build_aggregate_nodes` adds no scan, no traversal, and no new I/O.

The rejected alternative was carrying `example` on the wire beside `test`. That
would mean touching every language sidecar (C#, Swift, TypeScript, Go) to teach
each one a convention about the *workspace's* directory layout, and would leave
four implementations to drift. One central evaluation is the point of the change.

### D3 — `is_example_path` moves to its evaluation site

`EXAMPLE_SEGMENTS` + `is_example_path` move from `atlas/producer.rs` to
`aggregate.rs` as `pub(crate)`. The producer keeps one caller — the intra-package
sub-area computation, which ranges over *all* symbols in a package rather than
aggregate nodes, so it still needs the path form of the predicate.

The node-eligibility caller in the producer stops joining and reads `n.example`.

### D4 — Bump `STORE_SCHEMA_VERSION`

3 → 4. A snapshot written by the old code has no `example` column; reading it
would fail at the SELECT rather than at a checked boundary. The version check
turns that into the existing "reindex required" path. This is not the prototyping
version-churn the project avoids — it is the mechanism that already exists for
exactly this.

### D5 — The query stops carrying a documented gap

`tools/domains.rs` currently opens with a `KNOWN GAP` block explaining that it
fabricates `example: false`. That comment is deleted rather than reworded: the
gap is closed, and a stale caveat is worse than none.

## Risks / Trade-offs

- **Every snapshot must be rebuilt.** Accepted explicitly — the store is a
  derived artifact, and `kenn index` regenerates it. The schema-version bump
  makes the requirement loud instead of producing a confusing SQL error.
- **The domain count on this repo drops from 11 to 10.** That is the fix, not a
  regression: the disappearing domain was carried entirely by example binaries.
  Verification must confirm the *specific* domain disappears, not merely that a
  count moved.
- **`single_dominant` shifts on repos with large example trees.** Both surfaces
  compute it from the eligible set, so they shift together — but a repo whose
  examples were previously inflating one anchor's share could newly fall below
  the strict-majority threshold and lose its within-anchor domains. Correct, and
  worth watching on a real repo with a big `examples/` tree.
- **`fixtures` is in `EXAMPLE_SEGMENTS`.** Test fixture trees are excluded from
  domains under the existing convention; this change persists that behavior
  rather than revisiting it. Revisiting the segment list is out of scope.
